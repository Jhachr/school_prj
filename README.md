# school_prj

本仓库用于沉淀“专科院校教师科研助手”项目的完整上下文与交付资产。

项目采用“仓库即上下文”的工作方式：把客户沟通记录、需求理解、调研结论、交付用 Skill、展示材料和后续源码逐步放入同一个仓库，方便团队成员和 AI 助手在同一份上下文中持续迭代。

## 仓库结构

```text
.
├── customer-communications/
│   ├── raw/        # 客户访谈、会议纪要、聊天记录等原始材料
│   └── summaries/  # 基于原始材料整理出的需求总结、洞察和行动项
├── product-design/ # 用户流程、demo 脚本、质量标准和客户对齐材料
├── demo/           # 第一次客户沟通使用的纯前端流程验证 Demo
└── skills/         # 最终交付给客户使用的 Skill；当前先保留空目录
```

## 内容边界

### customer-communications

用于保存与客户沟通相关的上下文。

- `raw/`：只放原始内容，尽量保留客户原话、时间、参与人、来源和上下文。
- `summaries/`：放整理后的结论，包括客户目标、痛点、使用场景、决策记录、风险和下一步行动。

建议命名格式：

```text
YYYY-MM-DD-topic.md
```

### skills

用于沉淀项目的核心交付物，也就是未来交付给客户使用的科研助手 Skill。

当前阶段先保留目录，不初始化任何 Skill 文件。等客户需求和使用场景更清晰后，再创建具体 Skill。

### product-design

用于保存产品设计和 demo 设计材料。

当前第一版聚焦“小白老师不知道申报什么课题”的立项申请场景，重点沉淀：

- 用户流程
- demo 对话脚本
- 申报材料质量检查规则
- 客户资料清单

### demo

用于第一次客户沟通的网页流程验证 Demo。

它只展示流程、阻断条件、来源状态、A/B/C 质量判断和阶段性产物，不是正式产品运行时。正式版本将在成熟 Harness 中运行科研立项 Skill。
