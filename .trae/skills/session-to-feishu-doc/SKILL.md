# Session to Feishu Doc

把当前正在进行的完整会话原样保存为一个新的飞书云文档。内容包括：
- **对话正文**：用户与助手的逐轮消息（不摘要、不改写）
- **过程数据**：技能调用链路 + 工具调用日志（含参数与返回状态）

不做摘要、不改写、不省略（敏感信息除外，见脱敏规则）。

## 前置条件

- 本机已安装 `lark-cli` 并完成认证（`lark-cli auth status` 返回 `ok: true`）。
- 若未认证，告知用户运行 `lark-cli config init --new` 完成认证后再继续。

## 详细程度（detail level）

用户可指定过程数据的详细程度，默认 `summary`：

| 级别 | 对话正文 | 技能调用 | 工具调用 |
|------|----------|----------|----------|
| `full` | 完整 | 完整链路 + 触发原因 | 工具名 + 完整参数 + 完整返回 |
| `summary`（默认） | 完整 | 技能名 + 顺序 | 工具名 + 参数摘要（截断）+ 返回状态 |
| `none` | 完整 | 不包含 | 不包含 |

用户说"完整保存""全部过程数据""带上工具调用参数"等 → `full`。
用户说"只要对话""不要过程数据" → `none`。
未指定 → `summary`。

## 执行步骤

### 1. 重建会话与过程数据

从当前会话的第一条用户消息开始，逐条还原到最新一条消息。同时收集过程数据。

**对话正文**：
- 用户消息尽量逐字保留。
- 助手回复完整保留（包括代码块、列表、表格等结构）。

**过程数据**（detail 不为 `none` 时收集）：
- **技能调用链路**：每次 `Skill` 工具调用，记录技能名、调用顺序、加载的核心内容摘要。
- **工具调用日志**：每次工具调用，记录工具名、调用顺序、参数（summary 模式截断到约 200 字，full 模式完整）、返回状态（ok/error）、返回结果摘要（summary 模式截断到约 200 字）。
- 按时间顺序排列，与对话轮次对应。

**脱敏规则**（所有级别均生效）：
- 参数或返回中出现的 API key、token、密码、secret、authorization header 等敏感值，替换为 `[REDACTED]`。
- 识别依据：键名含 `key`、`token`、`secret`、`password`、`authorization`、`credential`，或值为明显的密钥格式（长随机字符串、`sk-` 前缀等）。
- 无法确定是否敏感时，保守打码。

### 2. 格式化为 Markdown

按下述结构写入：

```markdown
# 会话记录：[主题或日期]

- 日期：YYYY-MM-DD
- 轮次：N
- 详细程度：summary | full | none
- 涉及技能：[skill-a, skill-b, ...]
- 工具调用次数：M

---

## 一、完整对话

### 第 1 轮
**用户**：
[用户原话]

**助手**：
[助手完整回复]

### 第 2 轮
...

---

## 二、过程数据

### 1. 技能调用链路

| 序号 | 技能名 | 触发节点 | 核心内容摘要 |
|------|--------|----------|--------------|
| 1 | skill-a | 第 1 轮助手 | [摘要] |
| 2 | skill-b | 第 3 轮助手 | [摘要] |

### 2. 工具调用日志

| 序号 | 时间锚点 | 工具名 | 参数 | 返回状态 | 返回摘要 |
|------|----------|--------|------|----------|----------|
| 1 | 第 1 轮 | Skill | name: skill-a | ok | [摘要或 REDACTED] |
| 2 | 第 1 轮 | Read | file_path: ... | ok | [摘要或 REDACTED] |
| 3 | 第 2 轮 | Shell | command: ... | ok (exit 0) | [摘要] |
```

规则：
- 每一轮用 `### 第 N 轮` 分隔，N 从 1 开始递增。
- 角色标记固定为 `**用户**` 和 `**助手**`。
- 若会话有明确主题（如"科研方向探讨"），标题用主题；否则用日期。
- 文档中的代码块、表格、列表等 Markdown 结构原样保留。
- `detail = none` 时，省略「二、过程数据」整个章节及概览中的技能/工具统计。
- `detail = summary` 时，参数和返回摘要截断到约 200 字，超出部分用 `...（已截断）` 标记。
- `detail = full` 时，参数和返回内容完整写入（代码块包裹），不截断。
- 工具调用日志按时间顺序排列，「时间锚点」列填对应的对话轮次。

### 3. 写入本地临时文件

将上述 Markdown 写入**当前工作目录（CWD）**下的临时文件，例如：

```
./_session_export_YYYYMMDD.md
```

> 必须用相对路径写入 CWD，因为 `lark-cli` 的 `@file` 参数只接受 CWD 下的相对路径，传绝对路径会报 `unsafe file path`。

### 4. 创建飞书文档

调用辅助脚本：

```bash
node <skill-root>/scripts/create-doc.mjs --title "会话记录：[主题或日期]" --content "./_session_export_YYYYMMDD.md"
```

`<skill-root>` 是本 SKILL.md 所在目录。脚本内部执行：

```bash
lark-cli docs +create --doc-format markdown --title "..." --content "@./_session_export_YYYYMMDD.md" --as user
```

脚本会解析返回的 JSON，输出文档 URL。

### 5. 处理结果

- **成功**：向用户返回飞书文档 URL，并说明：已保存的轮次数、涉及的技能数、工具调用次数、使用的详细程度（detail level）。
- **未认证**（`not_configured`）：告知用户运行 `lark-cli config init --new` 完成认证后重试。
- **其他错误**：把 `lark-cli` 的错误信息原样展示给用户。

### 6. 清理

文档创建成功后，询问用户是否保留本地临时 Markdown 文件。默认不删除，等用户确认。

## 边界

- 只保存**当前会话**，不读取历史会话记录或其他本地文件。
- 对话正文不做改写或摘要；用户要求摘要时先说明本技能只做原样保存，再按需另外生成摘要。
- 过程数据的参数/返回在 `summary` 模式下会截断，`full` 模式下完整保留；但敏感信息始终脱敏。
- 不修改已有的飞书文档，每次都新建。
- 不主动删除本地临时文件，需用户确认。
