# 教师画像持久化与文献综述能力设计

日期：2026-10-25
状态：已完成方案讨论，待用户审阅书面规格
适用 Skill：`skills/research-proposal-coach/`

## 1. 背景

当前 `research-proposal-coach` 已经具备教师画像、文献综述、来源状态、Material Passport、阶段契约和质量规则的 Markdown 设计，但仍存在两个运行能力缺口：

1. 教师画像只存在于单次 session 状态中，无法跨会话复用。
2. 文献综述模块只有流程规则和输出模板，尚未具备真实公共学术源检索、规范化、去重、筛选、证据记录和引用核验能力。

客户沟通进一步明确了以下产品要求：

- 产品是科研导师或学伴，不是一键代写工具。
- 老师经常不知道要申报什么课题，系统必须主动进行研究扫描，而不能依赖老师先提供文献。
- 文献工作既要帮助老师理解研究现状，也要反向支撑选题、研究问题、方法、成果和创新点。
- 老师个人电脑是首版主要运行环境，通常一台电脑对应一位老师。
- 用户需要在新会话开始时选择“以 X 老师身份继续”或进入临时会话。
- 首版先接公共学术源，未来再接学校授权的知网和万方数据源。

## 2. 设计目标

### 2.1 用户画像与记忆

- 在老师个人电脑上持久保存经过确认的教师画像和长期有用的历史信息。
- 新会话开始时显式询问是否使用本机已有的 X 老师身份。
- 让老师看见系统准备复用哪些历史信息，并能纠正、删除或拒绝复用。
- 临时会话默认不读取、不写入教师档案。
- 不按工作目录或课题划分身份；同一老师的历史在本机全局可用。

### 2.2 文献能力

- 在老师尚未确定课题时，主动完成探索性的选题研究扫描。
- 在课题方向确认后，完成聚焦检索和有真实引用支撑的文献综述长稿。
- 保留检索式、数据源、时间、筛选过程、证据矩阵和论点—来源关系。
- 对公共数据源覆盖不足保持诚实，不把“查不到”自动解释为“文献不存在”或“研究空白”。
- 为未来知网、万方适配器预留稳定的文献记录契约。

### 2.3 安装与可移植性

- 保持“一条 CLI 命令安装整个能力包”的目标。
- 不要求老师单独安装数据库、后台服务或 MCP Server。
- Skill、规则、模板和辅助脚本随同一个包安装。
- 核心对话与判断规则继续使用 Markdown，避免绑定单一 Harness。

## 3. 非目标

首版不做：

- 多用户账号系统或学校单点登录。
- SQLite 或其他数据库。
- 常驻后台服务。
- 独立 MCP Server。
- 知网、万方的真实接入。
- 自动生成可直接投稿的学术论文。
- 在缺少真实申报模板和字段要求时生成通用“申报书文献综述”。
- 用 A/B/C 向老师评价科研水平或申报书质量。
- 保存完整聊天原文、学生敏感数据或账号凭证。

## 4. 总体架构

首版采用轻量方案：

```text
能力包
├── Markdown Skill、规则与模板
├── 随 Skill 安装的 Node.js 辅助脚本
└── 位于用户数据目录的 Markdown / JSONL 持久数据
```

职责划分：

```text
Skill
├── 会话入口与身份选择
├── 教师画像追问和确认
├── 记忆候选生成与确认
├── 检索策略生成
├── 文献相关性与证据判断
├── 主题综合和研究空白判断
└── 选题扫描与综述长稿生成

辅助脚本
├── 公共 API 请求
├── 分页、重试和限速处理
├── 原始结果保存
├── 字段规范化
├── 高置信重复项合并
└── 元数据与标识核验
```

辅助脚本属于 Skill 包的一部分，不构成单独需要安装的本地应用。

## 5. 本地数据目录

用户数据不得写入 Skill 安装目录，以免升级或重新安装时被覆盖。安装器或首次运行流程应解析当前操作系统的用户数据目录，并将结果作为 `RESEARCH_COACH_HOME`。在类 Unix 系统上的默认逻辑位置为：

```text
~/.research-proposal-coach/
├── teacher-profile.md
├── memories/
│   ├── research-history.md
│   ├── learning-feedback.md
│   └── preferences.md
├── sessions/
├── literature/
│   └── runs/
├── artifacts/
└── config/
```

Windows、macOS 和 Linux 的物理路径可由安装器分别解析，但 Skill 只依赖逻辑数据根目录，不硬编码平台路径。

`sessions/` 用于避免不同会话的过程文件互相覆盖，不代表用户需要创建或管理“项目”。身份、画像和记忆仍然是本机全局的。

## 6. 身份路由

### 6.1 首次使用

当 `teacher-profile.md` 不存在时：

1. 说明建立本地档案的用途和存储位置。
2. 征得用户同意。
3. 只追问完成初始画像所需的最小字段。
4. 展示画像摘要，请用户确认。
5. 确认后创建本地档案。

最小字段包括：

- 显示名称。
- 院系或专业领域。
- 岗位或主要职责。
- 至少一个具体课程或工作场景。
- 近期重点任务或已有科研基础。

### 6.2 再次使用

当 `teacher-profile.md` 已存在时，Skill 在进入科研流程前询问：

> 检测到本机的 X 老师档案，是否以 X 老师身份继续？

选择身份后，Skill 必须展示本次准备沿用的简要信息，并允许老师纠正。身份选择不等于无条件确认所有历史记录；核心事实在影响当前课题前仍需通过简短复核。

### 6.3 临时会话

选择不使用 X 老师身份时：

- 不读取教师画像和记忆。
- 不自动写入教师档案。
- 可以正常进行当前对话。
- 会话结束前可以询问是否将经用户确认的内容归档到 X 老师名下。
- 未获得明确同意时不归档。

## 7. 教师画像与长期记忆

### 7.1 教师画像格式

`teacher-profile.md` 使用 YAML frontmatter 保存机器稳定字段，正文使用可读表格：

```markdown
---
profile_id: local-teacher
display_name: 李老师
created_at: 2026-10-25
updated_at: 2026-10-25
memory_consent: true
---

# 教师画像

| 字段 | 内容 | 来源状态 | 最后确认时间 |
|---|---|---|---|
| 院系 | 管理学院 | user_confirmed（用户已确认） | 2026-10-25 |
| 岗位 | 专任教师 | user_confirmed（用户已确认） | 2026-10-25 |
| 主要课程 | 新媒体直播运营 | user_confirmed（用户已确认） | 2026-10-25 |
```

### 7.2 记忆分类

| 分类 | 典型内容 | 使用方式 |
|---|---|---|
| 稳定画像 | 院系、岗位、课程、职责 | 身份确认后推荐沿用 |
| 科研基础 | 项目、论文、教改、课程建设成果 | 推荐课题时主动关联 |
| 可用资源 | 班级、数据、企业案例、协作条件 | 判断课题可行性 |
| 研究历史 | 讨论过的方向和阶段产物 | 作为候选，不自动视为本次选择 |
| 交互偏好 | 快速版、深聊版、输出格式 | 调整引导方式 |
| 学习反馈 | 已表现出的长板、短板和阅读建议 | 提供针对性解释和建议 |

### 7.3 写入规则

不保存完整聊天记录。只有以下信息可以成为长期记忆候选：

- 用户明确确认的稳定事实。
- 用户作出的重要研究选择。
- 已形成并保存的研究方向或阶段产物。
- 对后续引导确有价值的偏好和学习反馈。

每个关键模块完成后可以形成记忆候选；会话结束前统一展示“本次建议记住”的条目，用户确认后才能写入。

不得保存：

- 身份证号、手机号等无关敏感信息。
- 学生个人信息和可识别成绩。
- 账号密码、Cookie、数据库凭证或 API key。
- 未经用户确认的系统推测。
- 完整原始聊天记录。

### 7.4 历史复用与冲突

历史信息复用流程：

```text
历史记录
-> suggested_from_history（根据历史推荐）
-> 向老师展示并允许纠正
-> 老师确认
-> user_confirmed（本次已确认）
```

当前回答与历史记录冲突时：

- 当前明确回答优先。
- 旧记录标记为 `superseded（已被新信息替代）`。
- 不静默覆盖历史。
- 下游依赖旧记录的产物标记为过期，等待重新确认或生成。

### 7.5 用户控制

Skill 必须支持老师通过自然语言完成：

- 查看系统记住的信息。
- 修改某条画像或记忆。
- 删除一条记忆。
- 导出完整个人档案。
- 删除全部个人档案与历史。

## 8. 文献能力总体流程

首版包含两次不同目的的检索和两个固定内容产物：

```text
教师画像 + 真实工作问题
-> 选题研究扫描
-> 2-3 个有依据的课题方向
-> 用户确认一个方向
-> 聚焦文献检索
-> 文献综述长稿
```

固定内容产物：

1. `选题研究扫描`：服务于尚不知道做什么课题的老师。
2. `文献综述长稿`：课题方向确认后的证据综合。

以下是支撑性过程产物，不直接等同于面向老师的正式内容产物：

- 检索计划。
- 原始检索记录。
- 规范化文献库。
- 筛选记录。
- 证据矩阵。
- 论点—来源记录。
- 检索覆盖与局限说明。

“申报书文献综述”不是文献模块的固定产物。只有真实申报模板、字段名称、字数限制和结构要求为 `material_verified（材料已核验）` 后，申报材料映射模块才能消费文献综述长稿并生成对应字段草稿。

## 9. 公共学术源

首版数据源分工：

- OpenAlex：主要发现源，用于作品搜索、过滤和相关文献发现。
- Crossref：用于 DOI、标题、作者、期刊和年份等出版元数据补全与核验。
- Semantic Scholar：作为后续增强源，用于相关论文、引用关系和推荐，不作为首版完成条件。
- 开放全文：优先使用检索记录提供的合法开放获取位置；只有获得合法全文或用户上传全文时才进行全文级证据判断。

Skill 不允许使用模型记忆生成参考文献。所有可引用文献必须来自保存的检索记录或用户提供的可追溯材料。

## 10. 辅助脚本

建议新增：

```text
scripts/
├── search-openalex.mjs
├── lookup-crossref.mjs
├── normalize-records.mjs
├── deduplicate-records.mjs
└── verify-metadata.mjs
```

脚本统一使用 JSON 输入输出，错误写入结构化错误结果并返回非零退出码。脚本不得直接生成综述论点。

首版安装入口与辅助脚本使用同一 Node.js 运行依赖。安装流程必须检测该运行依赖和对公共学术源的网络访问；失败时给出可执行的修复提示，不得显示虚假的安装成功。

未来新增知网或万方时，只增加适配器脚本或授权连接器。上层 Skill 和文献记录契约不变。

## 11. 检索运行目录

每次检索使用唯一运行目录：

```text
literature/runs/<run-id>/
├── search-plan.md
├── raw/
│   ├── openalex.json
│   └── crossref.json
├── corpus.jsonl
├── screening.jsonl
├── evidence-matrix.md
├── claim-ledger.jsonl
└── run-summary.md
```

`run-id` 由日期时间和短随机标识组成，避免覆盖。原始返回与规范化结果分开保存，确保后续可以复核和重新处理。

## 12. 统一文献记录

公共源以及未来学校数据源均输出统一记录：

```json
{
  "record_id": "openalex:W123",
  "source": "openalex",
  "source_record_id": "W123",
  "title": "string",
  "authors": [],
  "year": 2025,
  "doi": null,
  "venue": null,
  "abstract": null,
  "keywords": [],
  "url": "https://example.invalid/record",
  "open_access_url": null,
  "matched_queries": ["Q1"],
  "retrieved_at": "2026-10-25T00:00:00Z",
  "screening_status": "uncertain",
  "verification_status": "unresolved",
  "evidence_level": "candidate"
}
```

示例 URL 只说明字段形状，不进入任何真实产物或测试期望。

## 13. 两次检索的差异

### 13.1 选题研究扫描

输入：

- 教师画像。
- 至少一个真实课程或工作场景。
- 一个可观察的工作问题或问题域。
- 已知的学校、专业或政策方向。
- 可用资源和实践条件。

流程：

1. 将问题拆成研究对象、工作场景、核心问题和可能机制。
2. 生成多组中英文检索式，而非只检索一个完整句子。
3. 从公共源检索并取并集。
4. 规范化、保守去重和初步核验。
5. 进行 `included / uncertain / excluded` 三分类筛选。
6. 聚类主要主题、案例和可能空白。
7. 生成 2-3 个课题方向，每个方向显示依据、风险和覆盖限制。
8. 由老师确认一个方向后再进入聚焦检索。

选题扫描允许保留 `unresolved（暂未核验）` 线索，但不能让未决线索单独支撑确定性结论。

### 13.2 聚焦文献检索

输入：

- 已确认的课题方向。
- 初步研究问题和子问题。
- 第一次检索中的相关种子文献。

流程：

1. 将课题转成更聚焦的中英文检索式。
2. 补充同义词和相邻概念。
3. 重新检索并合并第一次检索中仍然相关的记录。
4. 必要时扩展高相关种子文献的引用和被引文献。
5. 进行相关性筛选和证据层级判断。
6. 构建文献—主题证据矩阵。
7. 识别一致结论、不同观点、方法局限和场景空白。
8. 与老师讨论本校或行业案例。
9. 创建论点—来源记录。
10. 生成文献综述长稿。

## 14. 去重策略

去重必须保守、可逆。

### 14.1 自动合并

仅对高置信重复项自动合并：

- DOI 完全一致。
- OpenAlex ID 完全一致。
- 同一数据源的稳定文献 ID 完全一致。

合并后的规范记录保留所有来源 ID 和首次命中查询。

### 14.2 疑似重复

标题高度相似、第一作者相同且年份接近时，只建立 `possible_duplicate（疑似重复）` 关系，不自动删除。以下情况必须保留版本关系：

- 预印本与正式发表版。
- 会议版与期刊扩展版。
- 中英文标题版本。
- 同一研究的阶段性成果。

### 14.3 低置信相似

只有关键词或标题结构相近时全部保留。

## 15. 筛选策略

相关性状态：

| 内部值 | 用户展示 | 含义 |
|---|---|---|
| `included` | `included（已纳入）` | 与当前问题明确相关 |
| `uncertain` | `uncertain（待判断）` | 可能相关，但信息不足 |
| `excluded` | `excluded（已排除）` | 明确不符合本轮标准 |
| `superseded` | `superseded（已有更完整版本）` | 被正式版或更完整记录替代 |

没有 DOI、缺少公开全文、只有中文标题、公共源没有摘要或 Crossref 未命中，都不能单独成为排除理由。

每条排除记录必须保存具体理由。课题方向变化时允许重新筛选，不必重新检索。

## 16. 核验与证据状态

### 16.1 文献身份核验

| 内部值 | 用户展示 | 含义 |
|---|---|---|
| `verified` | `verified（已核验）` | 标识与标题、作者、年份等信息能够匹配 |
| `unresolved` | `unresolved（暂未核验）` | 当前公共源无法确认，不代表文献不存在 |
| `conflicted` | `conflicted（信息冲突）` | DOI、标题、作者、年份或版本信息存在冲突 |
| `rejected` | `rejected（已排除）` | 标识明确不存在或记录明显错误，不允许进入引用 |

### 16.2 内容证据层级

| 内部值 | 用户展示 | 允许用途 |
|---|---|---|
| `candidate` | `candidate（候选线索）` | 用于扩展检索，不支撑最终论点 |
| `metadata_verified` | `metadata_verified（元数据已核验）` | 可说明该研究存在 |
| `abstract_supported` | `abstract_supported（摘要支持）` | 可作谨慎且不超出摘要的概括 |
| `fulltext_supported` | `fulltext_supported（全文支持）` | 可支撑有页码、章节或段落定位的具体论点 |

来源状态、身份核验状态、相关性状态和内容证据层级是不同维度，不得合并成一个模糊标签。

所有面向老师的英文状态值必须同时显示中文含义，并在首次出现时解释其对当前产物的影响。

## 17. 引用核验

引用核验分为三层：

1. 存在性：文献是否存在，标识是否可解析。
2. 绑定正确性：DOI、标题、作者、年份和版本是否属于同一文献。
3. 论点支持：摘要或全文是否真的支持当前句子。

最终文本中的每个重要论点必须写入 `claim-ledger.jsonl`：

```json
{
  "claim_id": "C01",
  "claim": "现有研究开始关注岗位任务与课程项目的衔接。",
  "source_ids": ["S01", "S04"],
  "support_level": "abstract_supported",
  "evidence_locations": ["abstract"],
  "limitations": ["尚未读取全文"]
}
```

生成文献综述时只能使用已经进入论点记录的来源，不允许临时凭模型记忆补充引用。

## 18. 检索不足与降级

检索不足时依次执行：

1. 检查查询式是否过窄或表达错误。
2. 扩展中英文同义词。
3. 放宽时间范围。
4. 拆分研究问题。
5. 扩展种子文献的引用网络。
6. 增加数据源。

仍然不足时，必须区分：

| 状态 | 用户展示 | 含义 |
|---|---|---|
| `research_gap` | `research_gap（可能的研究空白）` | 覆盖相对充分后仍缺少相关研究 |
| `source_coverage_gap` | `source_coverage_gap（数据源覆盖不足）` | 当前公共源对中文或本地研究覆盖不足 |
| `query_gap` | `query_gap（检索式可能不足）` | 查询词或查询结构需要调整 |
| `access_gap` | `access_gap（缺少摘要或全文）` | 文献存在但无法充分阅读 |

只有经过充分检索并排除其他缺口后，`research_gap（可能的研究空白）` 才能谨慎进入选题论证。

严格性只控制文献可以支撑多强的结论，不用于过早删除文献线索。

## 19. 文献综述长稿结构

长稿至少包含：

1. 检索范围与来源说明。
2. 核心概念和研究范围。
3. 按主题组织的研究现状。
4. 主要方法与已有实践路径。
5. 一致结论、分歧和反例。
6. 当前研究局限。
7. 对本课题研究问题、方法和成果的启发。
8. 公共数据源覆盖与全文访问限制。
9. 待老师补充的本校、行业或课程案例。
10. 可追溯参考文献列表。

该长稿是学习与课题设计产物，具备继续加工的基础，但不宣称可直接投稿。

## 20. 申报材料映射边界

申报书相关字段草稿只有在以下条件全部满足后生成：

- 真实申报模板为 `material_verified（材料已核验）`。
- 字段名称、结构和字数限制明确。
- 文献综述相关论点已经绑定来源。
- 老师确认需要保留的重点。

条件不满足时，系统只说明缺口，不生成通用压缩稿。压缩属于 `proposal_mapping` 模块，不属于文献综述模块。

## 21. 状态体系调整

现有 A/B/C 实际表示输出许可，而不是申报质量。它容易被误解为对老师或申报书打分，因此从新的规范状态中废弃。迁移期间可以读取旧字段，但写入新状态时必须使用下面的语义化值，面向用户也不得展示 A/B/C。

兼容迁移映射：

| 旧值 | 新输出许可 |
|---|---|
| C | `coaching_only` |
| B | `stage_artifact_ready` |
| A | `structured_draft_ready` |

该映射只用于迁移旧 session 和测试 fixture，不代表两套状态长期并存。

模块状态：

| 内部值 | 用户展示 |
|---|---|
| `blocked` | `blocked（暂时阻断）` |
| `needs_revision` | `needs_revision（需要修订）` |
| `ready` | `ready（已就绪）` |

输出许可：

| 内部值 | 用户展示 | 允许行为 |
|---|---|---|
| `coaching_only` | `coaching_only（仅继续引导）` | 追问、解释和方向建议 |
| `stage_artifact_ready` | `stage_artifact_ready（可生成阶段产物）` | 选题扫描、综述长稿等阶段产物 |
| `structured_draft_ready` | `structured_draft_ready（可生成申报结构稿）` | 在真实模板下生成结构化字段稿 |

用户界面和对话优先用自然语言说明“当前能做什么、为什么、还缺什么”，不要求老师理解内部状态码。输出许可也不等同于产物质量；产物质量继续由教师适配、问题真实性、证据充分性、方法可行性等各模块规则分别检查。

状态应按模块判断。缺少申报模板只阻断申报材料映射，不降低已经完成的文献综述状态。

## 22. 安装与升级

同一个安装包包含：

- Skill 入口文件。
- 规则、模块和模板。
- Node.js 辅助脚本。
- 用户数据目录初始化逻辑。
- 公共源连通性自检。

老师只执行一个由交付方提供的 CLI 安装命令。安装器完成 Harness Skill 安装、脚本安装、用户数据目录初始化和自检。

升级只替换 Skill、规则、模板和脚本，不覆盖 `RESEARCH_COACH_HOME` 中的用户数据。卸载 Skill 时默认保留用户数据，并明确提供单独删除个人数据的命令或交互步骤。

API key、数据库凭证和机构登录信息只能存放在本地配置或环境变量中，不得写入教师画像、记忆文件或检索产物。

## 23. 错误处理

### 23.1 文件与画像

- 数据目录不可写：停止持久化并说明如何选择可写目录；不得声称已保存。
- Markdown 格式损坏：保留原文件，创建带时间戳的诊断副本，并进入只读模式。
- 历史冲突：保留新旧值和确认时间，不静默覆盖。

### 23.2 检索

- API 不可用：保存检索计划和错误信息，尝试允许的备用源；不得生成虚假结果。
- 限速：按响应要求退避并保留进度。
- 部分数据源失败：对成功来源继续处理，并在运行摘要中明确覆盖缺口。
- 缺少摘要或全文：保留候选记录，降低证据层级，不直接排除。
- 元数据冲突：标记 `conflicted（信息冲突）`，不进入正式引用，等待补充核验。

### 23.3 上游变化

教师画像、课题方向或研究问题发生实质变化时，依赖旧值的检索计划、证据矩阵、论点记录和综述产物标记为过期。Skill 必须说明哪些内容需要重新检索或修订。

## 24. 测试与验收

### 24.1 教师画像

- 首次使用能够引导建档。
- 再次使用能够询问是否以 X 老师身份继续。
- 临时会话不读取、不写入个人档案。
- 历史信息先推荐、再确认。
- 新旧信息冲突时保留变更记录。
- 用户可以查看、修改、导出和删除记忆。

### 24.2 检索与规范化

- 模糊工作问题能生成多组中英文查询。
- 检索结果记录查询式、数据源、时间和命中关系。
- 相同 DOI 自动合并。
- 疑似重复项不被直接删除。
- 公共源无法核验的中文文献为 `unresolved（暂未核验）`，不是假文献。
- 网络失败时不生成虚假结果。

自动化测试使用固定 API 响应 fixture，避免 CI 依赖实时外部网络。另设显式运行的在线 smoke test 验证公共源当前可用性。

### 24.3 选题研究扫描

- 每个推荐方向都能追溯到教师画像、真实问题和检索线索。
- 能区分研究空白与数据源覆盖不足。
- 未核验线索不会写成确定性结论。
- 老师确认方向后才进入聚焦文献综述。

### 24.4 文献综述长稿

- 每个重要论点均对应文献记录。
- 只有摘要时不生成超出摘要的信息。
- 同时呈现一致结论、不同意见和研究局限。
- 文献不足时展示缺口，不编造引用。
- 没有真实申报模板时不生成申报书压缩稿。

### 24.5 状态与语言

- 所有面向老师的英文状态均同时显示中文含义。
- 用户输出不再展示 A/B/C。
- 状态按模块判断，并说明当前能做、不能做和下一步。

### 24.6 安装与升级

- 一条 CLI 命令安装 Skill、模板和脚本。
- 安装后完成数据目录与公共源连通性自检。
- 升级不覆盖个人数据和研究产物。
- 卸载默认不删除个人数据。

## 25. 分阶段实施顺序

1. 身份入口与 Markdown 教师画像。
2. 历史记忆读取、确认、纠正、删除和导出。
3. OpenAlex 检索脚本与原始结果保存。
4. Crossref 元数据补全和核验。
5. 规范化、保守去重和双语状态。
6. 选题研究扫描模块。
7. 聚焦检索、证据矩阵和论点—来源记录。
8. 文献综述长稿模块。
9. 一行安装、升级和回归测试。
10. 在获得正式授权和接口条件后增加知网、万方适配器。

## 26. 关键决策摘要

- 单机单老师场景不引入数据库或常驻本地服务。
- 身份路由、教师画像和长期记忆使用结构化 Markdown。
- 公共 API 调用和机械性处理使用随 Skill 安装的轻量 Node.js 脚本。
- 文献流程采用“宽进、分层、严出”，严格性控制引用强度，不用于过早丢弃候选文献。
- 文献核验使用多状态而非真假二元判断，并始终向老师提供中文解释。
- 首版固定内容产物只有选题研究扫描和文献综述长稿。
- 申报书相关字段必须等待真实模板，再由申报材料映射模块生成。
- A/B/C 从用户表达中移除，替换为模块状态与语义化输出许可。
