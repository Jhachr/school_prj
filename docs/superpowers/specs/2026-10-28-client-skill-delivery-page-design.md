# 科研教练 Skill 客户旅程式交付页设计

## 1. 目标

制作一个可在本地直接打开的中文单页 HTML，用于向非技术客户团队交付 `research-proposal-coach` Skill。页面既服务现场讲解，也能在会后作为自助阅读手册。

页面必须帮助客户回答五个问题：

1. 这次交付的是什么；
2. 它能帮助教师完成什么；
3. 一次完整使用会经历什么；
4. 用户如何开始使用；
5. 团队为了可靠交付做了哪些调研、设计和验证工作。

## 2. 受众与表达原则

- 第一受众是不了解 Skill、Agent 或代码的客户负责人和实际使用者。
- 使用“科研教练、使用旅程、阶段成果、质量提醒”等客户语言，不把目录、脚本或内部状态机作为主叙事。
- 技术细节只在“交付内容”和“研发与验证”中作为可信度证据出现。
- 不承诺自动生成可直接提交的最终材料；明确阶段材料仍需教师和专家复核。
- 所有能力、流程和数据必须能从当前仓库追溯，不使用未经验证的宣传数字。

## 3. 核心叙事

页面采用“客户旅程式交付页”。主角是教师，起点是一个模糊的教学或工作问题，终点是与目标匹配、证据可追溯、可以继续实施的结构化成果。

核心价值陈述：

> 它不是替教师一键代写，而是像科研教练一样，陪教师把真实问题逐步转化为研究问题、证据与设计、经过检查的工具或材料，以及可继续实施的教学改进、论文或课题申报成果。

## 4. 页面信息架构

### 4.1 开场区

- 项目名称：专科院校教师科研教练 Skill；
- 一句话价值；
- 两个入口：“查看一次完整旅程”“3 分钟了解如何使用”；
- 交付状态标签：“可移植 Skill 包”“面向真实教师场景”“规则与验证可追溯”。

### 4.2 为什么需要它

用三张简短问题卡说明客户原始痛点：教师不知道从哪里开始、通用 AI 容易直接生成表面完整的文本、研究过程和证据难以持续衔接。

本区必须明确“从代写提效转向引导教练”的产品定位来源于两轮客户沟通。

### 4.3 五阶段客户旅程

采用可点击或可聚焦的五阶段轨道：

1. 找到真实问题；
2. 明确目标与研究问题；
3. 建立证据与研究设计；
4. 开发并验证工具或材料；
5. 形成目标产物并安排实施。

每个阶段只展示四项客户信息：教师需要做什么、Skill 会如何帮助、会得到什么阶段结果、什么时候可以进入下一步。第四阶段标明“按研究需要启用，可说明原因后跳过”。

### 4.4 当前能力

以用户任务而非代码模块组织能力卡：

- 从真实场景发现选题；
- 把想法转化为可回答的研究问题；
- 组织文献和本地材料并标注证据边界；
- 设计研究对象、方法、指标和数据；
- 生成并检查量表、量规、课程包等工具材料；
- 将已有研究压缩为教学改进、论文或课题申报结构；
- 在旁支问题后返回主线；
- 在用户授权下复用教师画像与长期记忆；
- 识别提问疲劳、确认疲劳和质量风险。

### 4.5 三步上手

1. 选择实名教师模式或临时使用；
2. 用自己的话说明当前困惑，必要时提供已有材料；
3. 跟随每轮一个关键动作推进，并在阶段节点检查结果。

包含一段短示例，将“我想研究学生积极性”逐步转化为真实场景、研究问题、干预思路、观察指标和目标成果。示例必须明确是演示，不暗示已经存在实际研究结论。

### 4.6 可靠性与边界

采用“护栏”结构展示：

- 重要主张区分教师事实、系统建议、已核验材料、检索证据和缺失信息；
- 不编造文献、政策、学校要求或评审标准；
- 证据不足时不把阶段材料包装成正式申报书；
- 临时模式不读写长期画像；
- 长期记忆只保存教师明确确认的结构化信息；
- 目标变化时只复用仍然兼容的上游工作。

### 4.7 调研、设计与验证投入

采用“数字 + 含义”的方式展示当前仓库可验证事实：

| 事实 | 客户意义 |
|---|---|
| 2 轮客户需求沟通 | 产品定位与关键交互来自真实需求校准 |
| 5 阶段统一主流程 | 使用过程有清晰方向，也允许回退修正 |
| 9 个辅导模块 | 覆盖身份进入、选题、研究问题、文献、方法成果、创新、映射与学习反馈 |
| 9 组核心规则 | 固化来源、质量、记忆、协作、对话健康等边界 |
| 13 个模板 | 让阶段成果、质量报告和记忆复核可重复使用 |
| 24 个真实交互评测场景 | 覆盖模糊请求、目标切换、旁支问题、疲劳和证据风险 |
| 79 项自动化测试 | 持续检查关键行为和工具脚本是否退化 |

不把 5,641 行文件内容作为页面主指标，以免把工程体量误解为客户价值；可在交付清单中作为补充说明。

### 4.8 交付清单与使用建议

- Skill 主入口及可维护 Markdown 规则；
- 辅导模块、模板、检索与画像工具；
- 自动化测试与真实交互评估场景；
- Trae CN、Codex 和自定义目录安装入口；
- 客户第一周试用建议：选择 2—3 位不同科研基础的教师，各完成一次从真实问题到研究焦点的短流程，记录难懂术语、重复提问和期望产物。

### 4.9 常见问题

至少回答：是否代替教师思考、能否直接提交、是否支持论文和教学改进、是否会保存聊天内容、能否维护学校规则、后续如何反馈和迭代。

## 5. 交互设计

- 页面为无构建依赖的本地单页 HTML，配套独立 CSS 与少量原生 JavaScript；断网也能打开。
- 顶部导航在滚动时显示当前位置，窄屏改为紧凑导航。
- 五阶段旅程支持点击切换详情，同时保证不使用 JavaScript 时仍能阅读全部信息。
- 数字投入区使用进入视口后的轻量计数动画；尊重 `prefers-reduced-motion`。
- FAQ 使用原生 `details/summary`，键盘可操作。
- 不使用复杂图表、自动轮播或依赖外部 CDN 的组件。

## 6. 视觉设计

- 整体为温暖、可信、轻学术的编辑设计，不做科技蓝或后台仪表盘风格。
- 主色使用深墨绿和暖米色，辅色使用柔和珊瑚、浅黄与鼠尾草绿。
- 标题具有编辑感，正文保持高可读性；中文系统字体优先，避免联网字体依赖。
- 卡片、路径和注释使用轻手绘线条作为视觉语言，与插图保持一致。
- 页面在桌面投屏、笔记本阅读和手机纵向浏览下均保持清晰。

## 7. 插图方案

使用 `baoyu-article-illustrator`，设置为混合信息结构、均衡密度 4 幅、`sketch-notes` 教育手绘风、马卡龙配色、中文标签：

1. **旅程封面图**：教师从模糊问题出发，在科研教练陪伴下走向结构化成果；避免把 AI 画成机器人主角。
2. **五阶段流程图**：用连续路径表达阶段关系、可回退和条件阶段。
3. **人机协作图**：教师提供真实情境与决定，Skill 提供结构、证据提醒和方法建议，专家负责最终审阅。
4. **质量护栏图**：用来源、质量、隐私、对话健康四层护栏围绕研究成果。

插图中只保留短标签；较长解释放在 HTML 正文，降低中文文字生成错误风险。若图片文字错误，重新生成，不用程序覆盖修补。

## 9. 验收标准

- 双击 `index.html` 可在断网状态完整浏览；
- 主要内容在桌面和手机宽度下没有遮挡、横向溢出或不可读文字；
- 页面准确呈现五阶段流程、当前能力、使用方法、质量边界、研发投入和交付内容；
- 所有研发数字与当前仓库统计一致，并标明其客户意义；
- 所有交互可通过键盘完成，关闭 JavaScript 后核心内容仍可阅读；
- 4 幅插图风格一致、无明显乱码，并与对应章节内容直接相关；
- 页面不请求外部网络资源，不包含客户敏感信息或未经验证的承诺；
- README 说明如何打开、演示和整体复制交付目录。

## 10. 非目标

- 不在本次页面中实现 Skill 的安装器或运行界面；
- 不把页面发布到公网；
- 不制作客户品牌定制版或多语言版；
- 不加入后台数据、登录、表单提交或使用分析；
- 不把内部全部规则文件逐一展示给客户。
