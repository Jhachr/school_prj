# 轻量科研教练循环设计

## 背景

最新版 `research-proposal-coach` 已经实现教师可见语言简化、一次一个用户动作、场景化方向、研究骨架卡、目标切换和确认疲劳校正。本次不重做这些能力，只补足一个仍然偏抽象的环节：系统如何根据老师当前表达选择下一步动作，以及什么时候不应继续追问。

## 目标

让 Skill 在不增加独立 Agent、状态机或问题库的前提下，稳定执行一个轻量教练循环：

```text
理解当前表达
-> 判断最关键的一个缺口
-> 提供必要的最小支架
-> 需要时只问一个会改变方案的问题
-> 根据回答修订阶段成果
-> 达到条件后停止追问并推进
```

成功体验是：系统能主动发现研究漏洞，老师也能通过选择、修订、举例或说明理由拥有关键决定，同时不会因机械追问或重复确认而疲劳。

## 非目标

- 不新增教练 Agent、评审 Agent 或多 Agent 调度。
- 不新增第二套用户可见阶段或教练状态机。
- 不建立大型问题库、问题评分模型或复杂交互深度分数。
- 不以对话轮数作为科研质量的主要代理指标。
- 不修改现有画像、文献检索、来源状态、质量分级和 Material Passport 契约。

## 下一步动作选择

每轮先识别最关键的一种情况，只执行对应动作。多个情况同时存在时，优先处理会改变研究方向、方法、证据或成果的缺口。

| 当前情况 | 教练动作 | 用户可见结果 |
|---|---|---|
| 表达抽象，缺少可观察事实 | 请求一个具体课堂或工作例子 | 一个中心问题，可附一个短示例 |
| 老师不理解术语或方向 | 改写成课堂画面或通俗对比 | 不继续堆术语，也不立即追加新问题 |
| 信息足够，但老师不知道如何组织 | 给出一个紧凑草稿供修改 | 老师可直接改写或说“按这个做” |
| 存在逻辑、证据或可行性漏洞 | 说明一个最关键风险，再追问判断依据或反例 | 风险说明加一个决策性问题 |
| 老师卡住或无法选择 | 提供 2–3 个具体选项 | 保留组合、改写或自定义入口 |
| 老师已经选择、纠正、改写或说明理由 | 修订当前成果并推进 | 不再次要求形式化确认 |
| 老师出现确认疲劳或问题疲劳 | 汇总已有事实和决定 | 能推进则直接推进；不能推进时最多保留一个关键缺口 |

Skill 不需要向老师展示上述分类或内部判断。

## 最小支架原则

追问前只提供完成当前判断所需的最小帮助：

1. 镜像老师已经表达清楚的内容，避免让老师重复输入。
2. 用一句话说明当前缺口为什么影响研究质量。
3. 必要时给一个小草稿、课堂画面或有限选项。
4. 每轮默认只请求一个用户动作。

最小支架不是完整代写。未确认的系统草稿继续保持为系统建议；老师的修改、选择或继续指令才构成对决定的拥有。

## 停止追问条件

满足以下任一条件时，不再为了“体现教练感”追加问题：

- 老师已经提供足以支持当前阶段的具体事实。
- 老师通过选择、纠正、改写或说明理由拥有了当前决定。
- 新问题的答案不会改变研究方向、方法、证据、成果或结论边界。
- 当前阶段可以形成受限但诚实的阶段成果，剩余缺口可进入待补充清单。
- 对话健康已显示确认疲劳或系统自身制造疲劳。

如果核心事实、来源边界或可执行性仍不足，则停止生成大型产物，而不是无限追问；系统应汇总当前进展，指出唯一关键缺口，并保留返回入口。

## 与现有结构的关系

### `rules/guidance-principles.md`

在现有 `One-Action Response Pattern` 后增加“下一步动作选择”和“停止追问条件”。这是本次行为的唯一主要规则入口。

### `rules/dialogue-health.md`

复用现有绿色、黄色、红色状态。补充“已足够但仍追问”和“低价值细节追问”信号，并明确黄色状态可以无问题地直接推进。

### `SKILL.md`

只增加一条入口级不变量：先选择一个教练动作；如果停止条件成立，不为了完成流程而追加问题。避免复制完整判断表。

### 业务模块

不批量重写各模块，也不新增问题库。模块继续定义本阶段必需信息和产出；统一规则负责决定如何取得这些信息。

## 评测与测试

扩展现有 instruction-contract 测试和教练交互场景，覆盖：

1. 抽象表达只追问一个具体例子。
2. 老师看不懂术语时改成课堂画面，不继续堆问题。
3. 信息足够但表达零散时先给小草稿。
4. 逻辑或证据漏洞只挑一个最高风险追问。
5. 老师卡住时提供 2–3 个选项并允许改写。
6. 老师已作出有效选择后不重复确认。
7. 继续追问不会改变方案时直接推进。
8. 疲劳出现时允许回复中没有新问题。

测试重点是规则是否被正确接线。真实对话质量继续通过维护目录中的场景人工评审，不能只靠关键词测试宣称教练效果已经验证。

## 完成条件

- 现有教练交互、画像、文献和证据测试全部通过。
- Skill 能根据当前情况选择一种教练动作，并保持一次一个用户动作。
- 停止条件明确阻止重复确认和低价值追问。
- 没有新增 Agent、状态机、问题数据库或复杂评分模型。
- 源 Skill、安装副本和交付压缩包按现有发布流程保持一致。
