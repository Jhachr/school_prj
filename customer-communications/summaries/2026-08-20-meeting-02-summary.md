# 2026-08-20 第二次客户沟通总结

原始记录：`customer-communications/raw/0820_yipei_v1.txt`

## 一句话结论

客户认可 8 阶段流程骨架，但要求产品重心从"线性流程编排"升级为"模块化引导循环"——系统要像科研导师或学伴一样，在每个关键模块中引导老师思考、解释判断依据、追问薄弱环节，让老师在完成申报书的过程中提升科研理解。会后正式进入 Skill 开发阶段。

## 核心决策

### 1. 产品定位升级：从"代写提效"到"引导教练"

- 客户明确：工具的关键不在于帮老师更快完成材料，而在于引导老师做几个关键动作和关键思考，在做申报书的过程中提升对科研和对研究主题的深层理解。
- 系统角色是"师傅 + 学伴"，不是"奴仆"。可以帮老师做，但做的过程中会不停追问，而不是老师一句话就一键生成。
- 老师提不出好 prompt 是当前最大问题，系统的职责之一是引导老师知道应该问什么问题。

### 2. 可接受层级

| 层级 | 描述 | 说明 |
|---|---|---|
| 1.0（最低可接受） | 老师给有限输入，系统按内置规则生成阶段性材料 | 须至少追问一轮，降低"垃圾进垃圾出"风险 |
| 2.0（理想） | 系统在每个模块显式承担教练职责，引导老师理解什么是好问题、好方法、好成果、好创新点，并沉淀短板和学习建议 | 技术实现更复杂，但价值更大 |
| 长期 | 系统自学习优化 | 当前技术条件下无法承诺全自动自学习，但必须从第一版开始记录过程数据 |

### 3. 模块化引导循环

每个模块采用统一循环，取代线性串联：

```text
老师先输入想法
-> 系统生成草稿
-> 系统解释判断原则
-> 系统追问关键问题
-> 老师补充或确认
-> 系统修订草稿
-> 系统记录老师短板和学习建议
-> 进入下一模块或回退修正
```

模块之间允许往复。例如申报材料映射阶段发现课题不贴合前文，应回退到课题方向或研究问题模块，而非只在最终文本上润色。

### 4. 文献综述双输出

- 长文档：帮助老师理解研究现状和案例，可形成一篇可发表在学报上的论文，作为额外学习产物。
- 申报书字段版：把长文档压缩成符合申报书字数和结构要求的短段落。
- 老师与系统聊天不受字数限制，最后一步才做字数和结构压缩。

### 5. 质量评价指针（选题维度）

客户提出评价课题的维度，作为选题引导指针：

1. 是否延续教师已有科研基础。
2. 是否解决实际工作中的真实问题。
3. 方法或思路上是否有显著创新性。
4. 是否符合学校专业群建设、重大项目、政策导向（如提质培优、最新职业教育提法）。

课题不必满足所有维度，可有侧重，但每个维度应尽量考虑。

### 6. 研究问题与方法成果的引导原则

- 研究问题：最多 3-5 个，关系应并列互补（互斥穷尽）或递进；要引导老师区分"问题"与"口号""任务""成果"。
- 方法：必须是一套具体的工作体系、工具、流程、量表或案例库，而非空泛理念；每个方法对应要解决的问题。
- 成果：不能只有论文，至少要有一个可复用、工具性、流程性或实践改进类成果；可基于科研处评分标准提示成果评分风险。
- 创新点：结合前文文献和案例提炼，必须能被前文材料支撑，不能凭空拔高。

### 7. 交互深度作为质量辅助评判

如果系统部署为单点登录工具，可通过老师与系统交互的深度（聊了多少轮、是否主动补充案例）辅助判断申报书撰写深度。直接要求"帮我写吧"且不交互的老师，质量风险更高。

### 8. 交付形态：可移植 Skill 包

- 交付物为一系列可打包的 Skill 包，核心规则使用 Markdown，方便非技术 owner 维护。
- Skill 运转在 harness 之上（如 Trae），但不绑死单一平台；核心流程、质量规则和输出契约不写死在某个平台里。
- 工具能力通过适配层接入（飞书、文献检索、学校材料等），避免把平台能力直接写进核心规则。
- 客户可维护内容（Markdown）与工程适配代码分离。

### 9. 维护与评测 loop

- 客户侧由 1-3 人（非技术大拿即可）维护各模块 Markdown 文件，如更新学校科研要求、补充优秀案例、调整优先级。
- 长期目标是自学习优化 loop，但当前阶段是 human-in-the-loop：先搭建观测和记录能力，知道系统发生了什么、为什么发生，再逐步减轻人工介入。
- 左侧先建评测 loop（定义什么算好的结果），右侧才建能力 loop（让 agent 变强）。

## 会议遗留事项

### 我方待办

1. 将产品重心从"线性流程编排"升级为"模块化引导循环"，沉淀为 Skill 包结构和规则。
2. 建立过程日志机制，记录每个模块的进出时间、追问内容、来源状态变化和质量等级变化。
3. 调研现有方案和学校老师的真实评价标准，建立选题引导指针和质量规则。
4. 设计可移植 Skill 包的目录结构和交付形式。
5. 搭建观测和评测旁路，收集 agent 与客户沟通的关键信息。

### 客户侧支持

1. 提供优秀课题申报书样例。
2. 提供学校申报书模板和格式要求。
3. 提供课题申报指南、政策文件或征集通知。
4. 协助访谈科研处、教务处或优秀申报教师。
5. 补充客户自己对"好申报书"的判断标准和成果评分要求。
