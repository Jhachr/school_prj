# Method And Outcome Design Module

## Purpose

Make the proposal implementable by mapping each research problem to methods, actions, data, and outcomes.

## Required Inputs

- Confirmed research question.
- Available class, project, work, data, or collaboration resources.
- Expected cycle.
- School outcome requirements when available.

## Coaching Loop

1. Draft a problem-method-outcome table.
2. Explain that a method should be a concrete work system, tool, process, rubric, case library, or implementation path.
3. Identify empty concepts or methods that could apply anywhere.
4. Ask for resource, sample, data, and cycle details.
5. Check that at least one non-paper outcome exists.
6. Revise outcomes and mark scoring risks.

## Pass Conditions

- Each major problem has a plausible method path.
- Method path includes object, action, data/resource, cycle, and evaluation.
- At least one non-paper outcome is confirmed.

## Output

```markdown
### Problem-Method-Outcome Map

| Problem | Method/Action | Data Or Resource | Outcome | Source Status | Risk |
|---|---|---|---|---|---|
```

## Fallback

If outcomes are only papers, suggest 2-4 reusable artifacts that fit the topic and ask the teacher which are realistic.
