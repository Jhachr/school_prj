# Session Sharing Module

## Purpose

在合适的会话结束节点，允许老师自愿把当前会话提交给产品改进团队。会话上传是独立的反馈动作，不推进研究阶段，也不写入教师画像或长期记忆。

## When To Offer

只有在以下节点之一出现时，才可以主动提议：

- `delivery_and_action` 已形成当前目标产物；
- 会话明确结束或暂停，准备等待老师补充外部材料；
- 老师主动询问如何反馈、上传或提交当前会话。

每次会话只主动提议一次。拒绝后不追问；沉默、继续讨论或接受研究产物都不算同意。是否上传不影响科研教练的任何功能。

主动提议时直接给出一次知情确认，不增加“先准备摘要、再确认上传”的中间轮次。建议使用一句低压力文案：

> 如果你愿意帮助我们改进科研教练，我可以把本次当前可见会话脱敏后保存到你的飞书，并将脱敏正文和文档链接发送到“科研教练产品改进群”；默认包含完整对话和简要工具过程，不包含隐藏消息或内部推理。不同意不会影响继续使用。是否确认上传？

老师明确同意这份包含范围和去向的摘要后，即视为本次上传授权。若首次使用还需飞书配置或扫码授权，完成后继续同一事务，不再次询问接收者或要求二次确认上传。沉默、继续讨论或只接受研究产物不算同意。

## Direct Requests

老师主动说“上传这次对话”“把当前会话提交给产品团队”时，暂停主线，把当前阶段保存到 `resume_phase`，读取并使用 `session-to-feishu-doc`。展示一次包含范围、脱敏方式和固定接收群的确认摘要；不得因为用户主动提出就直接上传或省略知情确认，也不得再增加“是否准备摘要”或“发送给谁”的问题。

完成、取消或失败后恢复研究主线。上传成功本身不推进研究阶段，不改变质量等级，也不成为长期记忆事实。

## Session-Only State

```json
{
  "session_share_offer": "not_offered",
  "session_share_requested": false
}
```

`session_share_offer` 只允许：

- `not_offered`：尚未主动提议；
- `offered`：已展示确认摘要，等待老师决定；
- `declined`：老师拒绝，本次不再提议；
- `completed`：上传事务成功完成。

该状态只存在当前会话，不写入教师档案。上传失败可在老师主动要求时重试，但不得自动重复创建文档。
