# 专科院校教师科研立项引导助手

## 01 客户诉求

客户希望系统帮助老师把课题想清楚，而不是简单替老师写材料。

核心诉求：

- 引导老师明确要解决什么真实问题。
- 引导老师说明准备用什么方法解决。
- 基于真实文献检索和前沿研究，帮助老师判断课题切入点。
- 形成文献综述草稿，帮助老师理解过去研究了什么、还有什么问题没解决。
- 引导老师设计不止论文的可复用成果。
- 把老师朴素表达转化为申报书准备材料。

## 02 产品定位

本期产品定位：

```text
科研立项引导助手
```

它像科研申报教练，通过有规则的对话帮助老师从真实教学或工作问题出发，形成可申报课题方案。

本期不把产品定位为：

- 简单代写工具
- 论文写作工具
- 完整科研生命周期管理系统

## 03 首版边界

首版只验证一个场景：

```text
小白老师不知道申报什么课题
```

本次网页验证不现场实现：

- 实时联网文献检索 API 调用
- DOCX 自动填充
- 完整知识库
- 高阶教师场景
- 学校系统集成
- 正式可提交申报书

正式科研立项 Skill 必须支持真实文献检索、前沿研究匹配和文献综述草稿生成。本次网页用演示数据展示该流程和产物形态。

## 04 8 阶段流程

```text
1. 教师画像采集
2. 空泛意图纠偏
3. 工作问题挖掘
4. 课题方向推荐与确认
5. 研究问题澄清
6. 文献与政策支撑
7. 方法与成果设计
8. 申报材料生成与质检
```

每个阶段都有输入要求、阻断条件、追问策略、阶段产物和人工确认点。

## 05 差异化能力

普通大模型自由聊天容易直接给答案。我们的流程强调：

- 空泛输入不直接生成。
- 推荐课题前先确认教师画像和真实问题。
- 课题推荐结合申报指南和相关方向前沿研究。
- 文献综述草稿显示来源状态，不能伪造引用。
- 每个关键结论显示来源状态。
- 质量不足时继续追问。
- B 级只生成阶段性材料，不生成正式申报书草稿。

## 06 直播电商 Demo

本次选择学校专业目录中的：

```text
管理与数字经济学院 - 网络营销与直播电商
```

演示起点：

```text
我想做 AI+教育，帮我写个课题申报。
```

系统将其收敛为：

```text
岗位任务导向的直播电商实训教学改革研究
```

选择该专业，是因为官网信息显示其具有实践性、技术性、多元性，课程体系与行业产业需求紧密结合，并具备直播实训室、摄影实训室、营销实训室和综合直播基地。

## 07 五项结果

本次 Demo 展示五项阶段产物：

1. 课题方案卡：问题、对象、方法、成果、依据、风险。
2. 文献综述草稿：研究现状、前沿趋势、已有不足、本课题切入点。
3. 申报书字段映射稿：把已确认内容放入通用申报书栏目。
4. 待补充清单：模板、指南、文献检索来源、优秀案例、评审标准。
5. 质量结果：当前为 B 级，可生成阶段性材料。

当前不生成正式申报书草稿，因为真实申报指南、真实文献检索结果和学校模板尚未完整接入。

## 08 正式交付架构

本次网页只是为了让第一次沟通更直观。正式版本应在成熟 Harness 中运行科研立项 Skill：

```text
教师
-> 成熟 Harness
-> 科研立项 Skill
-> 模型 / 工具 / 学校材料
-> 课题方案卡 / 文献综述草稿 / 字段映射稿 / 申报书结构化内容
```

客户本轮确认的是业务流程、判断规则和产物结构。确认后的规则将进入后续 Skill 建设。

## 09 需要客户确认

会议中希望客户确认：

- 是否认可科研立项引导助手定位。
- 是否认可首版只聚焦小白老师立项申请。
- 是否认可 8 阶段流程和关键人工确认点。
- 是否认可课题方案卡、文献综述草稿、字段映射稿、待补充清单和质量结果。
- 哪些质量规则需要科研处或专家补充。

## 10 下一步安排

第一次 Demo 结束后进入第二版真实材料 Demo：

- 客户提供学校申报书模板。
- 客户提供本期申报指南或征集通知。
- 客户确认可用文献检索来源、关键词范围和文献综述要求。
- 客户提供 1-3 份脱敏优秀申报书。
- 客户补充评审标准、常见退回意见或专家判断。
- 我方将业务规则沉淀到科研立项 Skill 建设中。
