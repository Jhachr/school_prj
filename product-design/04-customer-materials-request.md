# 客户资料清单

## 用途

这份清单用于向客户说明下一阶段需要哪些材料，以便把 demo 从“流程验证”推进到“贴近学校真实申报”的版本。

## P0：下次 demo 前最需要

| 材料 | 用途 | 备注 |
|---|---|---|
| 课题申报书空白模板 | 确定最终生成结构 | Word/PDF 均可 |
| 1-3 份优秀申报书 | 学习学校认为“好”的材料长什么样 | 可脱敏 |
| 最近一次课题申报指南或征集通知 | 判断申报方向和政策导向 | 校级、省级均可 |
| 评审标准或打分表 | 建立质量检查规则 | 如果没有正式表，可访谈获取 |
| 客户对“好申报书”的口头判断 | 补充隐性标准 | 可通过访谈整理 |

## P1：设计进阶场景需要

| 材料 | 用途 |
|---|---|
| 老师过往课题材料 | 支持“已有科研基础老师申报更高层级课题” |
| 学校重点专业、重点建设方向 | 推荐更符合学校战略的课题方向 |
| 科研处常见退回意见 | 形成系统追问和质量检查规则 |
| 优秀教师访谈 | 学习成熟申报者如何构思课题 |
| 审核侧老师访谈 | 学习评审者如何判断好坏 |

## P2：后续产品化需要

| 材料 | 用途 |
|---|---|
| 学校知识库资料 | 建立学校专属上下文 |
| 历年立项结果 | 分析哪些方向更容易立项 |
| 结题材料样例 | 将来扩展到结题报告或成果管理 |
| 教师科研画像字段 | 支持千人千面推荐 |
| 学校系统或文档平台要求 | 支持后续集成 |

## 资料收集责任表

现有资料清单内容不变,以下补充负责人、提供时间、脱敏方式和无法提供时的替代方案,确保每项材料都有明确归属和兜底路径。

| 材料 | 优先级 | 负责人 | 提供时间 | 脱敏方式 | 无法提供时的替代方案 |
|---|---|---|---|---|---|
| 课题申报书空白模板 | P0 | 客户科研处对接人 | 下次 demo 前 | 无需脱敏(空白模板) | 先用通用模板演示,拿到学校模板后替换栏目 |
| 1-3 份优秀申报书 | P0 | 客户科研处对接人 | 下次 demo 前 | 去除姓名、单位、联系方式等个人信息 | 用公开省级优秀课题范例替代,标注为外部参考 |
| 课题申报指南或征集通知 | P0 | 客户科研处对接人 | 下次 demo 前 | 无需脱敏(公开文件) | 用上级主管部门公开申报指南替代 |
| 评审标准或打分表 | P0 | 客户科研处或评审专家 | 下次 demo 前 | 无需脱敏 | 通过访谈整理口头标准,记录为隐性规则 |
| 客户对"好申报书"的口头判断 | P0 | 客户方项目负责人 | 访谈时记录 | 访谈记录去标识 | 由我方基于优秀范例推断,标注为推断标准 |
| 老师过往课题材料 | P1 | 试点教师 | 进阶场景启动前 | 去除个人与单位敏感信息 | 暂不采集,首版不依赖 |
| 学校重点专业/建设方向 | P1 | 客户方教务或科研处 | 进阶场景启动前 | 无需脱敏(公开信息) | 用学校官网公开信息替代 |
| 科研处常见退回意见 | P1 | 客户科研处 | 进阶场景启动前 | 去除具体申报人信息 | 通过访谈评审专家推断常见问题 |
| 优秀教师/审核侧访谈 | P1 | 客户方协调 | 进阶场景启动前 | 访谈记录去标识 | 用公开教研经验材料替代 |
| 学校知识库资料 | P2 | 客户信息中心 | 产品化阶段 | 按学校数据治理要求 | 暂不采集,首版不依赖 |
| 历年立项结果 | P2 | 客户科研处 | 产品化阶段 | 去除申报人信息 | 用公开立项公示替代 |

> 责任表与客户确认清单(`07-customer-confirmation-checklist.md`)第七项联动:会议现场需明确 P0 材料的责任人与提供时间,并记录脱敏方式与替代方案是否被客户接受。

## 建议发给客户的话术

> 为了让下一版 demo 更贴近学校真实科研申报场景，我们希望先收集几类材料：申报书模板、优秀申报书样例、最近的申报指南、评审标准或科研处常见意见。我们会先用于流程和质量标准校准，不会直接对外展示原文；如涉及敏感信息，可以先提供脱敏版本。

## 材料使用原则

1. 原始材料只作为事实依据，不直接混入总结判断。
2. 涉及个人或学校敏感信息时优先脱敏。
3. 优秀案例不能简单复制，要提炼结构、标准和判断逻辑。
4. 客户口头经验要沉淀为可追问、可检查的规则。
