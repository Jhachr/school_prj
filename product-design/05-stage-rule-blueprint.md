# 阶段规则蓝图

## 用途

这份文档把用户流程转换为可执行的阶段规则，后续可直接指导 Agent、Skill 或普通应用流程建设。

核心结构：

```text
阶段 -> 输入字段 -> 阻断条件 -> 追问策略 -> 输出字段 -> 确认状态
```

## 全局状态字段

| 字段 | 说明 | 来源 |
|---|---|---|
| `teacher_profile` | 教师画像 | 用户确认 |
| `raw_intent` | 用户最初表达 | 用户原话 |
| `problem_candidates` | 候选工作问题 | AI 整理，需用户确认 |
| `topic_options` | 候选课题方向 | AI 生成，需用户选择 |
| `selected_topic` | 已选择课题方向 | 用户确认 |
| `research_question` | 核心研究问题 | AI 草拟，用户确认 |
| `evidence_basis` | 文献、政策、指南、案例依据 | 材料依据或演示数据 |
| `method_plan` | 研究方法路径 | AI 建议，用户确认 |
| `deliverables` | 预期成果 | AI 建议，用户确认 |
| `proposal_mapping` | 申报书字段映射 | AI 生成，需人工复核 |
| `missing_items` | 待补充信息 | 系统识别 |

## 证据来源标记

所有关键结论必须标记来源：

| 标记 | 含义 |
|---|---|
| `用户确认` | 用户明确说过或确认过 |
| `AI推测` | AI 基于上下文推断，尚未确认 |
| `材料依据` | 来自申报指南、政策、模板或文献 |
| `演示数据` | demo 中模拟材料，只用于展示流程 |
| `待验证` | 需要客户或专家补充确认 |

## 阶段状态表

| 阶段 | 必须输入 | 阻断条件 | 追问策略 | 输出字段 | 确认状态 |
|---|---|---|---|---|---|
| 1. 教师画像采集 | 院系/岗位/课程或工作/近两年重点工作 | 不知道老师具体工作场景 | 追问课程、对象、日常任务、学校要求 | `teacher_profile` | 用户确认 |
| 2. 空泛意图纠偏 | 用户初始想法 | 只有“AI+教育”“提升质量”等口号 | 追问具体课程、学生群体、教学环节、可获得数据 | `refined_problem_area` | 用户确认 |
| 3. 工作问题挖掘 | 具体痛点或改进目标 | 没有真实问题或问题不可观察 | 追问发生频率、影响对象、现有做法、失败原因 | `problem_candidates` | 用户选择 |
| 4. 课题方向推荐 | 教师画像 + 问题候选 | 问题和教师工作无关 | 生成 2-3 个方向，说明理由和风险 | `topic_options` | 用户选择 |
| 5. 研究问题澄清 | 已选方向 | 没有研究对象、场景、目标或评价方式 | 用“对象-场景-问题-方法-评价”框架追问 | `research_question` | 用户确认 |
| 6. 文献与政策支撑 | 申报指南/政策/模拟材料 | 没有任何依据且未标注演示数据 | 明确哪些来自材料，哪些待验证 | `evidence_basis` | 用户知情 |
| 7. 方法路径设计 | 研究问题 + 可用资源 | 方法不可执行或数据不可得 | 追问样本、周期、数据、实施班级或部门 | `method_plan` | 用户确认 |
| 8. 成果形式设计 | 方法路径 + 申报要求 | 只有论文，没有可复用成果 | 引导形成工具、流程、案例、量表、资源包 | `deliverables` | 用户确认 |
| 9. 申报材料生成 | 前序确认字段 | 硬性门槛缺失 | 只生成摘要，不生成完整初稿 | `proposal_mapping` | 人工复核 |
| 10. 质量检查 | 申报材料草稿 | 发现硬伤 | 输出风险和待补充清单 | `missing_items` | 客户/老师确认 |

## 用户异常输入处理

| 情况 | 处理策略 |
|---|---|
| 用户回答模糊 | 不进入下一阶段，给出 2-4 个选择题帮助收敛 |
| 用户拒绝回答 | 说明该信息影响哪些输出；允许跳过但标为 `待补充` |
| 用户中途改方向 | 保留旧方向到备选区，重新进入方向确认 |
| 用户要求直接生成 | 如果硬性门槛缺失，只生成方案摘要和缺口清单 |
| 用户上传材料但未说明用途 | 先识别材料类型，再询问用于政策、模板、案例还是过往成果 |

## 阶段通过原则

1. 不因用户说“可以”就默认通过，必须满足字段条件。
2. AI 推测不能替代用户确认。
3. 演示数据不能伪装成真实文献或政策依据。
4. 硬性门槛缺失时，不生成完整申报书初稿。
5. 所有待补充项必须进入最终输出。
