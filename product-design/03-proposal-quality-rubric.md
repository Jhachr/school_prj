# 申报书质量检查表

## 用途

这份检查表用于定义科研助手在立项申请流程中如何判断“老师是否已经想清楚”，以及什么时候应该继续追问，什么时候可以生成申报书初稿。

## 检查维度

| 维度 | 达标表现 | 常见问题 | 追问方向 |
|---|---|---|---|
| 真实问题 | 问题来自教师实际教学、管理或服务场景 | 问题太空，如“提升教学质量” | 具体发生在哪门课、哪个环节、哪类学生身上？ |
| 问题具体性 | 有明确对象、场景、痛点和改进目标 | 范围太大或只有口号 | 你最想解决其中哪一个具体问题？ |
| 申报价值 | 与学校发展、专业建设、教学改革或政策导向有关 | 只是个人工作总结 | 这个问题为什么值得作为课题研究？ |
| 研究问题 | 能用一句话说明要研究什么 | 只有课题名称，没有研究问题 | 你想验证、改进或形成什么结论？ |
| 方法路径 | 方法与问题匹配，数据可获得 | 方法堆砌，无法执行 | 你准备从哪里获得数据或案例？ |
| 成果形式 | 至少包含一个可复用的非论文成果 | 只有论文或结题报告 | 其他老师能复用什么工具、流程或资源？ |
| 文献/政策支撑 | 能说明已有研究、政策要求和本课题切入点 | 文献只是装饰 | 哪些已有研究没解决你的具体问题？ |
| 学校模板适配 | 内容能填入申报书各板块 | 聊得清楚但无法落表 | 申报书这一栏需要哪些固定信息？ |
| 可实施性 | 周期、资源、对象和数据都现实可行 | 想法好但条件不足 | 你能在哪个班级、课程或部门先试点？ |
| 创新性 | 有场景、方法、工具或成果上的具体改进 | 空泛说“创新” | 和过去做法相比，具体新在哪里？ |

## 质量等级

### A：可以生成申报书初稿

满足条件：

1. 已确认课题方向。
2. 研究问题具体。
3. 有可执行方法。
4. 至少有一个非论文成果。
5. 能说明与教师真实工作场景的关系。

系统动作：

```text
生成申报书初稿，并标注仍需客户补充的证据或材料。
```

### B：可以生成方案摘要，但不生成完整申报书

满足情况：

1. 方向基本明确，但研究问题仍偏泛。
2. 方法初步可行，但数据来源不清楚。
3. 成果形式有想法，但还不够具体。

系统动作：

```text
生成课题方案摘要，并继续追问薄弱环节。
```

### C：继续引导，不生成申报材料

出现情况：

1. 老师还没有明确工作问题。
2. 课题方向和教师工作关系不清楚。
3. 只是想写论文，没有课题研究对象和实践场景。
4. 研究范围过大，无法在课题周期内实施。

系统动作：

```text
返回工作场景和问题挖掘阶段。
```

## 必须追问的风险信号

| 风险信号 | 为什么危险 | 系统追问 |
|---|---|---|
| “我想做 AI+教育” | 方向太大，没有场景 | 具体是哪门课、哪个学生群体、哪个教学环节？ |
| “最终发一篇论文” | 成果单一，不符合客户强调的工具性 | 除论文外，能形成什么可复用成果？ |
| “提升学生能力” | 目标不可测 | 具体提升哪种能力？如何观察或评价？ |
| “用问卷调查一下” | 方法可能流于形式 | 问卷要验证什么？样本从哪里来？ |
| “参考政策要求” | 可能只是贴政策 | 哪条政策和你的课题直接相关？ |
| “学校都需要这个” | 缺少具体对象 | 先在哪个专业、课程或部门试点？ |

## 最小通过标准

第一版 demo 中，系统只要能判断以下 6 个问题即可：

1. 老师是谁？
2. 老师遇到的真实问题是什么？
3. 这个问题能否转成课题？
4. 准备用什么方法解决？
5. 最终产出什么可复用成果？
6. 是否能写进学校申报书模板？
