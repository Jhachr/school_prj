# 申报书质量检查表

## 用途

这份检查表用于定义科研助手在立项申请流程中如何判断"老师是否已经想清楚",以及什么时候应该继续追问,什么时候可以生成申报书初稿。

本文档是质量判断的中枢规则,驱动系统自动完成等级判定、阻断决策与产出物分发。它与以下两份文档配套使用:

- `05-stage-rule-state-table.md`(阶段规则):定义各阶段必须收集的输入字段、阻断式通过条件与输出字段。本文档引用其中的输出字段名作为"证据字段",二者字段命名保持一致。
- `06-deliverable-templates.md`(交付物模板):定义课题方案卡与申报书字段映射稿两份可视化交付物的模板。本文档判定达到 A 级后,按该模板生成对应交付物。

字段状态标记(已确认 / AI推测 / 待补充)的含义与处理方式,沿用 `05-stage-rule-state-table.md` 的定义,本文档不再重复。

## 检查维度

| 维度 | 达标表现 | 常见问题 | 追问方向 | 证据字段 |
|---|---|---|---|---|
| 真实问题 | 问题来自教师实际教学、管理或服务场景 | 问题太空,如"提升教学质量" | 具体发生在哪门课、哪个环节、哪类学生身上? | `pain_point`, `scenario` |
| 问题具体性 | 有明确对象、场景、痛点和改进目标 | 范围太大或只有口号 | 你最想解决其中哪一个具体问题? | `target_object`, `scenario` |
| 申报价值 | 与学校发展、专业建设、教学改革或政策导向有关 | 只是个人工作总结 | 这个问题为什么值得作为课题研究? | `school_req`, `policy_link` |
| 研究问题 | 能用一句话说明要研究什么 | 只有课题名称,没有研究问题 | 你想验证、改进或形成什么结论? | `core_question` |
| 方法路径 | 方法与问题匹配,数据可获得 | 方法堆砌,无法执行 | 你准备从哪里获得数据或案例? | `method_type`, `data_source`, `steps` |
| 成果形式 | 至少包含一个可复用的非论文成果 | 只有论文或结题报告 | 其他老师能复用什么工具、流程或资源? | `outcomes[]`, `non_paper` |
| 文献/政策支撑 | 能说明已有研究、政策要求和本课题切入点 | 文献只是装饰 | 哪些已有研究没解决你的具体问题? | `research_status`, `policy_link`, `entry_point` |
| 学校模板适配 | 内容能填入申报书各板块 | 聊得清楚但无法落表 | 申报书这一栏需要哪些固定信息? | `proposal_draft` 各栏目填充率 |
| 可实施性 | 周期、资源、对象和数据都现实可行 | 想法好但条件不足 | 你能在哪个班级、课程或部门先试点? | `feasibility`, `resource_available` |
| 创新性 | 有场景、方法、工具或成果上的具体改进 | 空泛说"创新" | 和过去做法相比,具体新在哪里? | `method_plan` 或 `outcome_list` 中的改进点 |

证据字段使用说明:

- 证据字段名与 `05-stage-rule-state-table.md` 各阶段输出字段保持一致。
- 判断某维度是否通过时,系统先检查对应证据字段是否存在、是否非空、确认状态为何。
- 字段缺失或标记为 `待补充` → 该维度不通过。
- 字段存在但标记为 `AI推测` → 该维度通过但需在交付物中标注风险,进入下一阶段前请用户确认。
- 字段标记为 `已确认` → 该维度通过。

## 硬性门槛与可补充项

十维检查中,部分维度构成"硬性门槛",缺失则系统阻断,无法生成完整申报书初稿;另一部分维度构成"可补充项",允许生成初稿但必须在交付物中标注风险与待补充说明。

### 硬性门槛

缺失任意一项,系统阻断完整初稿生成,返回对应阶段追问。

| 门槛项 | 判定要求 | 对应证据字段 | 缺失时系统动作 |
|---|---|---|---|
| 真实问题 | 必须有来自教师实际场景的具体问题 | `pain_point` | 回退阶段 3 工作问题挖掘 |
| 研究问题 | 必须能用一句话表述核心研究问题 | `core_question` | 回退阶段 6 研究问题澄清 |
| 方法路径 | 必须有与问题匹配的方法且数据来源可获得 | `method_type`, `data_source` | 回退阶段 8 方法路径设计 |
| 成果形式 | 必须至少有一个非论文可复用成果 | `non_paper` | 回退阶段 9 成果形式设计 |
| 方向确认 | 必须经用户人工确认选定方向 | `selected_direction` | 回退阶段 5 方向确认 |

### 可补充项

允许在缺失或为推测时生成初稿,但必须在课题方案卡"主要风险""待补充信息"栏和申报书字段映射稿"确认状态"列中明确标注。

| 补充项 | 缺失或推测时的处理 | 标注方式 |
|---|---|---|
| 申报价值 | 可标注为待客户/科研处确认 | 确认状态标 `待补充`,来源依据注明"待客户或科研处确认" |
| 文献/政策支撑 | 首版可用演示数据 | 内容前缀 `【演示数据】`,确认状态标 `AI推测` |
| 学校模板适配 | 暂无客户模板时用通用模板 | 申报书栏目使用通用模板栏目,顶部注明"通用模板,待替换为学校真实模板" |
| 创新性 | 可基于方法/工具/场景改进推断 | 确认状态标 `AI推测`,来源依据注明"基于方法/工具/场景改进推断" |
| 可实施性 | 周期资源可后续细化 | 确认状态标 `待补充`,在"主要风险"栏注明"周期与资源待细化" |

## 质量等级

### A:可以生成申报书初稿

满足条件:

1. 已确认课题方向。
2. 研究问题具体。
3. 有可执行方法。
4. 至少有一个非论文成果。
5. 能说明与教师真实工作场景的关系。

证据要求:

- 全部硬性门槛已满足(真实问题、研究问题、方法路径、成果形式、方向确认五项对应字段均已存在且非空)。
- 可补充项(申报价值、文献/政策支撑、学校模板适配、创新性、可实施性)均已按上节规则标注风险或待补充说明,不存在未标注的缺失项。

系统动作:

```text
1. 生成申报书初稿(proposal_draft),每栏目标注确认状态与来源依据。
2. 生成课题方案卡(一页),见 06-deliverable-templates.md 第一节。
3. 生成申报书字段映射稿,见 06-deliverable-templates.md 第二节。
4. 在交付物中汇总标注所有可补充项的风险与待补充信息,进入客户确认清单追踪。
```

### B:可以生成方案摘要,但不生成完整申报书

满足情况:

1. 方向基本明确,但研究问题仍偏泛。
2. 方法初步可行,但数据来源不清楚。
3. 成果形式有想法,但还不够具体。

证据要求:

- 至少一项硬性门槛未满足(对应字段缺失或标记 `待补充`)。
- 但方向已确认(`selected_direction` 存在),不构成 C 级的"方向或问题未明确"。

系统动作:

```text
1. 生成课题方案摘要(方案卡的简化版,仅含已确认字段,缺口栏目标注待补充)。
2. 针对未满足的硬性门槛,返回对应阶段追问(阶段 3/6/8/9 之一)。
3. 不生成申报书字段映射稿,不生成完整申报书初稿。
4. 追问结果需用户确认后方可重新进入质量检查。
```

### C:继续引导,不生成申报材料

出现情况:

1. 老师还没有明确工作问题。
2. 课题方向和教师工作关系不清楚。
3. 只是想写论文,没有课题研究对象和实践场景。
4. 研究范围过大,无法在课题周期内实施。

证据要求:

- 方向未确认(`selected_direction` 缺失),或真实问题缺失(`pain_point` 缺失),或问题具体性缺失(`target_object`、`scenario` 均缺失)。

系统动作:

```text
1. 回退到工作问题挖掘(阶段 3)或方向确认(阶段 5)阶段。
2. 持续追问具体场景、对象、教学环节,不生成任何申报材料。
3. 仅当用户补充至方向明确且真实问题具体后,重新进入质量检查流程。
```

## 必须追问的风险信号

| 风险信号 | 为什么危险 | 系统追问 |
|---|---|---|
| "我想做 AI+教育" | 方向太大,没有场景 | 具体是哪门课、哪个学生群体、哪个教学环节? |
| "最终发一篇论文" | 成果单一,不符合客户强调的工具性 | 除论文外,能形成什么可复用成果? |
| "提升学生能力" | 目标不可测 | 具体提升哪种能力?如何观察或评价? |
| "用问卷调查一下" | 方法可能流于形式 | 问卷要验证什么?样本从哪里来? |
| "参考政策要求" | 可能只是贴政策 | 哪条政策和你的课题直接相关? |
| "学校都需要这个" | 缺少具体对象 | 先在哪个专业、课程或部门试点? |

## 最小通过标准

第一版 demo 中,系统只要能判断以下 6 个问题即可:

1. 老师是谁?
2. 老师遇到的真实问题是什么?
3. 这个问题能否转成课题?
4. 准备用什么方法解决?
5. 最终产出什么可复用成果?
6. 是否能写进学校申报书模板?

## 测试案例

以下三套案例用于验证十维检查、硬性门槛判定与系统动作分发的正确性。每套案例包含输入场景、各维检查结果、判定等级与系统动作。

### 案例 1:合格(A 级)

输入场景:

- 教师:张老师,智能制造学院,机械制图课程。
- 真实问题:学生实践课参与度不高,作业质量差,课堂任务与企业真实岗位脱节。
- 方法:行动研究 + 案例研究,数据来源为企业岗位任务调研与课堂作业评分。
- 成果:论文 1 篇、岗位任务案例库 1 套、项目作业评价量表 1 套、课堂实施方案 1 份。
- 方向:已由用户人工确认选定"岗位任务导向的实践教学改革"方向。

各维检查结果:

| 维度 | 判定 | 说明 |
|---|---|---|
| 真实问题 | 通过 | `pain_point`、`scenario` 已确认,来自实际教学场景 |
| 问题具体性 | 通过 | `target_object` 为专科大一学生,`scenario` 为机械制图项目作业环节 |
| 申报价值 | 待补充 | `school_req` 待客户/科研处确认,标注风险 |
| 研究问题 | 通过 | `core_question` 可一句话表述并经用户确认 |
| 方法路径 | 通过 | `method_type`、`data_source`、`steps` 齐全且数据可获得 |
| 成果形式 | 通过 | `non_paper` 为真,含案例库、评价量表、实施方案 |
| 文献/政策支撑 | 待补充 | 首版用演示数据,标注 `【演示数据】` |
| 学校模板适配 | 待补充 | 暂用通用模板,标注待替换 |
| 可实施性 | 待补充 | 试点班级与周期待细化,标注风险 |
| 创新性 | 待补充 | 基于方法/工具改进推断,标注 `AI推测` |

判定等级:A

- 全部硬性门槛(真实问题、研究问题、方法路径、成果形式、方向确认)已满足。
- 可补充项均已按规则标注风险或待补充说明。

系统动作:

1. 生成申报书初稿,各栏目标注确认状态与来源依据。
2. 生成课题方案卡(一页)。
3. 生成申报书字段映射稿。
4. 在交付物中标注:企业任务来源待补充、文献为演示数据、学校模板待替换、创新点为 AI 推测、周期资源待细化。

### 案例 2:边界(B 级)

输入场景:

- 教师:李老师,想研究"信息化教学"。
- 真实问题:只有方向没有具体场景,未说明哪门课、哪类学生、哪个教学环节。
- 方法:初步考虑用问卷调查,但数据来源不清楚,样本未明确。
- 成果:只有论文 1 篇,无非论文可复用成果。
- 方向:用户已选定"信息化教学"方向,但选择理由不具体。

各维检查结果:

| 维度 | 判定 | 说明 |
|---|---|---|
| 真实问题 | 待补充 | `pain_point` 缺失具体场景,仅有方向性表述 |
| 问题具体性 | 不通过 | `target_object`、`scenario` 均缺失 |
| 申报价值 | 待补充 | `school_req` 未涉及 |
| 研究问题 | 待补充 | `core_question` 偏泛,无法一句话落到对象+场景+改进目标 |
| 方法路径 | 不通过 | `data_source` 不清楚,样本来源未明确 |
| 成果形式 | 不通过(硬性门槛缺失) | `non_paper` 为假,只有论文 |
| 文献/政策支撑 | 待补充 | 未涉及 |
| 学校模板适配 | 待补充 | 内容无法落表 |
| 可实施性 | 待补充 | 周期、对象、数据均不明确 |
| 创新性 | 待补充 | 无具体改进点 |

判定等级:B

- 至少一项硬性门槛未满足:成果形式(`non_paper`)缺失、方法路径(`data_source`)缺失。
- 方向已确认(`selected_direction` 存在),不构成 C 级。

系统动作:

1. 生成课题方案摘要(仅含已确认字段,缺口栏目标注待补充)。
2. 追问具体课程和学生群体(回退阶段 3 工作问题挖掘)。
3. 追问非论文可复用成果(回退阶段 9 成果形式设计)。
4. 不生成申报书字段映射稿,不生成完整申报书初稿。

### 案例 3:不合格(C 级)

输入场景:

- 教师:王老师,输入"我想做 AI+教育"。
- 真实问题:无具体课程、无学生群体、无教学环节。
- 方法:未涉及。
- 成果:未涉及。
- 方向:未确认,拒绝细化具体场景。

各维检查结果:

| 维度 | 判定 | 说明 |
|---|---|---|
| 真实问题 | 不通过(缺失) | `pain_point` 缺失 |
| 问题具体性 | 不通过(缺失) | `target_object`、`scenario` 均缺失 |
| 申报价值 | 待补充 | 未涉及 |
| 研究问题 | 不通过(缺失) | `core_question` 缺失 |
| 方法路径 | 不通过(缺失) | `method_type`、`data_source` 缺失 |
| 成果形式 | 不通过(缺失) | `outcomes[]`、`non_paper` 缺失 |
| 文献/政策支撑 | 待补充 | 未涉及 |
| 学校模板适配 | 待补充 | 无内容可落表 |
| 可实施性 | 待补充 | 无条件信息 |
| 创新性 | 待补充 | 无具体改进点 |

判定等级:C

- 方向未确认(`selected_direction` 缺失)。
- 真实问题缺失(`pain_point` 缺失)。
- 问题具体性缺失(`target_object`、`scenario` 均缺失)。

系统动作:

1. 回退到工作问题挖掘(阶段 3),不进入方向确认及后续阶段。
2. 持续追问:具体是哪门课、哪个学生群体、哪个教学环节。
3. 不生成任何申报材料,仅当用户补充至方向明确且真实问题具体后,重新进入质量检查流程。
