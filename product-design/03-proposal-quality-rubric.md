# 申报书质量检查表

## 用途

这份检查表用于驱动系统判断：什么时候继续追问，什么时候只生成方案摘要，什么时候可以生成申报书初稿。

核心原则：

```text
硬性门槛缺失 -> 不生成完整初稿
可补充项缺失 -> 可以生成，但必须标注风险
AI 推测内容 -> 必须标记，不能当作用户确认
演示数据 -> 必须标记，不能伪装成真实依据
```

## 质量检查维度

| 维度 | 证据字段 | 达标表现 | 不达标表现 | 缺失类型 |
|---|---|---|---|---|
| 真实问题 | `problem_candidates` | 来自具体教学/工作场景 | 只有口号或宏大方向 | 硬性门槛 |
| 问题具体性 | `research_question` | 有对象、场景、痛点、目标 | “提升质量”“AI+教育”未收敛 | 硬性门槛 |
| 教师适配 | `teacher_profile` | 与教师课程/岗位相关 | 方向和教师工作脱节 | 硬性门槛 |
| 方法可执行 | `method_plan` | 有数据、对象、周期、实施路径 | 方法堆砌或数据不可得 | 硬性门槛 |
| 非论文成果 | `deliverables` | 至少一个可复用成果 | 只有论文或结题报告 | 硬性门槛 |
| 申报价值 | `evidence_basis` | 能说明与学校/政策/专业建设相关 | 只是个人经验总结 | 可补充项 |
| 政策依据 | `evidence_basis` | 有指南、政策、征集方向或明确演示标记 | 没有依据且未标注 | 可补充项 |
| 文献支撑 | `evidence_basis` | 有研究现状或待检索标记 | 伪造文献或无依据 | 可补充项 |
| 创新点 | `proposal_mapping.innovation` | 能说明具体改进 | 空泛说“创新” | 可补充项 |
| 模板适配 | `proposal_mapping` | 能映射到申报书字段 | 内容散乱无法入表 | 可补充项 |

## 硬性门槛

缺失任一硬性门槛时，不生成完整申报书初稿。

| 门槛 | 必须满足 | 缺失时动作 |
|---|---|---|
| 真实问题 | 至少一个来自真实工作场景的问题 | 回到工作问题挖掘 |
| 研究对象和场景 | 明确课程/学生/部门/工作环节 | 继续追问对象和场景 |
| 教师资源条件 | 教师能接触研究对象或材料 | 调整课题范围 |
| 方法可执行 | 有数据来源或实施路径 | 只生成方案摘要 |
| 非论文成果 | 至少一个工具、流程、案例、量表、资源包等 | 追问成果形式 |

## 可补充项

缺失可补充项时，可以生成初稿，但必须标注风险和待补充信息。

| 可补充项 | 缺失影响 | 输出标记 |
|---|---|---|
| 真实申报指南 | 无法判断是否完全贴合本期申报方向 | `待客户提供指南` |
| 学校申报模板 | 无法保证字段完全匹配 | `暂用通用模板` |
| 优秀申报书样例 | 质量标准缺少校内参照 | `待补充优秀案例` |
| 评审标准 | 创新性和价值判断可能偏泛 | `待科研处确认` |
| 文献来源 | 研究现状可能不充分 | `待真实检索` |

## A/B/C 生成规则

### A：可生成申报书初稿

必须满足：

1. 所有硬性门槛通过。
2. 课题方向已由用户确认。
3. 研究问题已由用户确认。
4. 方法路径已由用户确认。
5. 成果形式已由用户确认。
6. 可补充项缺失已明确标记。

允许输出：

- 申报书初稿
- 课题方案卡
- 字段映射稿
- 待补充清单

### B：只生成方案摘要和字段草稿

出现任一情况：

1. 硬性门槛基本满足，但方法或成果仍不够细。
2. 政策、文献、模板均未接入真实材料。
3. 用户确认不足，但方向已有较高可信度。

允许输出：

- 课题方案摘要
- 字段映射草稿
- 风险标注
- 追问清单

不允许输出：

- 完整正式申报书
- 未标注依据的文献综述

### C：不生成申报材料

出现任一情况：

1. 只有空泛方向。
2. 没有真实问题。
3. 课题和教师工作场景无关。
4. 没有可执行方法。
5. 成果只有论文且用户拒绝补充。

允许输出：

- 问题澄清提问
- 方向收敛建议
- 示例选项

## 测试案例

### 案例 A：合格

输入：

> 我教新媒体直播运营，学生会模仿直播话术，但不会根据商品和人群写脚本，也不会做直播数据复盘。我能提供学生直播脚本、实训评分表、直播数据截图和企业项目案例，希望形成直播任务包、评价量表和复盘模板。

判断：

- 真实问题：通过
- 研究对象和场景：通过
- 方法可执行：通过
- 非论文成果：通过
- 政策/文献/模板：可补充

输出等级：A 或 B。若真实模板未接入，则输出 B；若模板和指南已接入，可输出 A。

### 案例 B：边界

输入：

> 我想做 AI+教育，最好能和学生学习效果有关。

判断：

- 真实问题：不通过
- 场景：不通过
- 方法：不通过
- 非论文成果：不通过

输出等级：C。

系统动作：

```text
拒绝直接生成申报书，追问课程、学生群体、教学环节和数据来源。
```

### 案例 C：不合格

输入：

> 帮我写一个关于提升教学质量的课题，成果就写论文。

判断：

- 问题具体性：不通过
- 方法可执行：不通过
- 非论文成果：不通过

输出等级：C。

系统动作：

```text
说明当前无法形成申报材料，引导用户提供真实教学场景和可复用成果。
```

## 首次 Demo 的最小判断能力

第一版 demo 只需要可靠完成以下判断：

1. 空泛方向是否需要纠偏。
2. 是否有真实教学或工作问题。
3. 是否有明确课程/学生/场景。
4. 是否有可执行方法。
5. 是否有非论文成果。
6. 哪些内容来自用户确认，哪些只是演示材料或待验证建议。
