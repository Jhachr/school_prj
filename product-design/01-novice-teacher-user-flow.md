# 小白老师立项申请用户流程

## 文档定位

本文件是本期业务流程源文档。它只定义第一次客户验证轮使用的唯一流程模型：客户视角 8 个业务阶段，系统内部 10 个执行状态。

首版场景聚焦：专科院校中缺少科研申报经验、尚未形成明确课题方向的一线教师或行政/教辅老师。

## 用户目标

老师通过聊天式引导，把自己的岗位背景、教学或工作痛点、学校要求和初步想法，逐步转化为可讨论、可修改、可进入申报书字段的课题方案。

系统不是简单代写工具，而是科研立项教练。它必须在关键节点判断信息是否充分，不充分时继续追问，不能越过质量门槛生成申报材料。

## 客户视角 8 个业务阶段

```text
1. 教师画像采集
2. 空泛意图纠偏
3. 工作问题挖掘
4. 课题方向推荐与确认
5. 研究问题澄清
6. 文献与政策支撑
7. 方法与成果设计
8. 申报材料生成与质检
```

## 8 阶段与 10 个内部状态映射

| 客户阶段 | 内部状态 | 客户感知产出 |
|---|---|---|
| 1. 教师画像采集 | `teacher_profile` | 教师画像摘要 |
| 2. 空泛意图纠偏 | `intent_refinement` | 收敛后的问题域 |
| 3. 工作问题挖掘 | `problem_discovery` | 候选工作问题 |
| 4. 课题方向推荐与确认 | `topic_recommendation` | 2-3 个课题方向候选 |
| 4. 课题方向推荐与确认 | `topic_confirmation` | 用户选择的课题方向 |
| 5. 研究问题澄清 | `research_question` | 核心研究问题草案 |
| 6. 文献与政策支撑 | `evidence_support` | 依据说明和待验证标记 |
| 7. 方法与成果设计 | `method_and_outcomes` | 方法路径和成果清单 |
| 8. 申报材料生成与质检 | `proposal_mapping` | 课题方案卡、申报书字段映射稿 |
| 8. 申报材料生成与质检 | `quality_checking` | A/B/C 质量结果和待补充清单 |

## 阶段设计

| 阶段 | 目标 | 必须获得的信息 | 阻断条件 | 核心产出 |
|---|---|---|---|---|
| 教师画像采集 | 知道老师是谁、做什么、有什么真实场景 | 院系、岗位、课程或工作、近两年重点任务 | 只知道姓名职称，不知道具体教学或管理场景 | 教师画像摘要 |
| 空泛意图纠偏 | 拒绝“AI+教育”“提升质量”等空泛输入 | 初始想法、具体课程、学生群体、教学环节、数据来源 | 只有口号，没有对象、场景和问题 | 收敛后的问题域 |
| 工作问题挖掘 | 从日常工作中提取可研究问题 | 痛点、发生频率、影响对象、现有做法、失败原因 | 问题不可观察，或与教师工作无关 | 候选工作问题 |
| 课题方向推荐与确认 | 给出可比较的申报方向 | 教师画像、候选问题、可用资源、申报导向 | 真实问题未确认，或资源条件明显不足 | 课题方向候选卡、已选方向 |
| 研究问题澄清 | 把方向变成可研究的问题 | 对象、场景、问题、方法、评价方式 | 只有课题名称，没有可回答问题 | 核心研究问题 |
| 文献与政策支撑 | 说明为什么值得做 | 真实政策/指南/模板/文献，或明确标记的演示数据 | 无任何依据且未标记演示数据 | 依据说明 |
| 方法与成果设计 | 形成能实施、能结题的方案 | 方法路径、数据来源、实施周期、非论文成果 | 方法不可执行，或成果只有论文 | 方法路径、成果清单 |
| 申报材料生成与质检 | 生成阶段性材料并暴露缺口 | 前序确认字段、来源状态、质量结果 | C 级条件成立 | 方案卡、字段映射稿、待补充清单、质量结果 |

## 来源状态

所有关键内容必须标记来源状态：

| 来源状态 | 含义 |
|---|---|
| `user_confirmed` | 用户明确表达或确认 |
| `ai_suggestion` | AI/系统建议，尚需用户采纳 |
| `material_verified` | 来自可追溯真实材料 |
| `demo_fixture` | 演示占位数据，不是真实依据 |
| `missing` | 当前缺失 |

`demo_fixture` 永远不能因为用户说“可以”而变成 `material_verified`。正式版本必须用客户提供的真实材料替换。

## 关键人工确认点

系统必须在以下节点暂停：

1. 课题方向确认。
2. 研究问题确认。
3. 政策/申报指南适配确认。
4. 方法路径和数据来源确认。
5. 成果形式确认。
6. 申报材料字段映射复核。

## 第一版不做

1. 不做完整科研生命周期。
2. 不做真实文献检索自动化。
3. 不做 DOCX 自动填充。
4. 不做高阶教师场景。
5. 不做学校系统集成。
6. 不把 B 级阶段性产物称为完整申报书初稿。
