# 小白老师立项申请用户流程

## 目标用户

专科院校中缺少科研申报经验、尚未形成明确课题方向的一线教师或行政/教辅老师。

## 用户目标

老师通过聊天式引导，把自己的岗位背景、教学或工作痛点、学校要求和初步想法，逐步转化为一个可以进入课题申报书的研究方案。

## 设计目标

1. 帮老师发现可研究的问题。
2. 帮老师判断问题是否值得申报。
3. 帮老师设计方法和成果形式。
4. 帮老师生成符合申报书结构的初稿。
5. 在关键节点让老师确认，而不是全自动代写。

## 流程总览

```text
入口说明
-> 教师画像采集
-> 工作问题挖掘
-> 课题方向推荐
-> 方向确认
-> 研究问题澄清
-> 文献与政策支撑
-> 方法路径设计
-> 成果形式设计
-> 申报书初稿生成
-> 质量检查与追问
-> 定稿导出
```

## 阶段设计

### 1. 入口说明

系统告诉老师：这不是直接代写工具，而是一个科研立项引导助手。老师只需要用自己的话回答问题，系统会逐步帮助整理成申报书材料。

关键提示：

- 可以从很朴素的工作问题开始。
- 不需要一开始就知道课题名称。
- 过程中会多次让老师确认。

### 2. 教师画像采集

目标：了解老师是谁、做什么、有什么可转化为课题的工作场景。

需要采集：

- 所属院系或部门
- 岗位角色
- 教授课程或负责工作
- 近两年重点工作
- 过往科研或项目经验
- 学校或部门对其工作的要求

质量判断：

- 如果回答只有职称和姓名，继续追问具体工作场景。
- 如果没有教学或管理场景，追问最近反复遇到的问题。

### 3. 工作问题挖掘

目标：从日常工作中提取真实、具体、可研究的问题。

提问方向：

- 教学中最想改善的环节是什么？
- 学生在哪些地方表现不理想？
- 目前工作流程中最耗时或最不稳定的部分是什么？
- 学校或领导最近最关注哪些改进方向？
- 有没有一个问题反复出现，但还没有系统解决？

质量判断：

- 问题必须来自真实场景。
- 问题不能过大，例如“提升教学质量”需要继续细化。
- 问题要能落到对象、情境、原因或改进目标上。

### 4. 课题方向推荐

目标：基于教师画像和工作问题，给出 2-3 个可申报方向。

每个方向包含：

- 暂定课题名称
- 对应的真实问题
- 研究对象
- 可能的方法
- 预期成果
- 适合申报的理由
- 主要风险

系统不直接替老师决定方向，而是让老师选择最有兴趣、最有资源、最符合学校要求的一项。

### 5. 方向确认

目标：让老师明确选择一个方向，并说明为什么选它。

确认问题：

- 这个方向是否确实来自你的工作？
- 你是否有条件开展这个研究？
- 学校或部门是否会认可这个方向？
- 你希望这个课题最终改变什么？

质量判断：

- 如果老师只说“听起来可以”，继续追问其工作关联。
- 如果资源条件不足，提示降低范围或调整研究对象。

### 6. 研究问题澄清

目标：把方向变成可研究的问题。

需要形成：

- 核心研究问题
- 研究对象
- 研究场景
- 当前痛点
- 改进目标
- 评价方式

示例结构：

```text
在某类专科学生/课程/管理场景中，当前存在什么问题？
为什么这个问题值得研究？
本课题准备用什么方法改进？
如何判断改进是否有效？
```

### 7. 文献与政策支撑

目标：帮助老师理解已有研究、政策方向和申报依据。

第一版 demo 中可先模拟这一阶段，不必接入真实检索。

输出内容：

- 研究现状概括
- 已有研究不足
- 政策或学校要求关联
- 本课题切入点

质量判断：

- 文献综述不是堆文献，而是服务于“为什么这个课题值得做”。
- 政策文件不是装饰，而要解释课题与申报导向的关系。

### 8. 方法路径设计

目标：把“想法”变成可执行的研究方案。

常见方法：

- 问卷调查
- 访谈
- 课堂观察
- 行动研究
- 案例研究
- 教学实验或前后测
- 工作流程改造与效果评估

质量判断：

- 方法要和问题匹配。
- 数据来源要现实可获得。
- 实施周期要符合课题周期。

### 9. 成果形式设计

目标：避免成果只有论文，满足客户强调的工具性、流程性、可复用性。

成果可以包括：

- 论文
- 教学案例
- 工作流程
- 评价量表
- 课程资源包
- 操作手册
- 校本实践方案
- 数据分析报告
- 可复用工具或模板

质量判断：

- 至少包含一个非论文成果。
- 成果要能被其他老师或部门复用。
- 成果要能回应前面的研究问题。

### 10. 申报书初稿生成

目标：基于前面已确认的信息，生成申报书初稿。

建议初稿结构：

- 课题名称
- 研究背景与意义
- 国内外/校内外研究现状
- 研究目标
- 研究内容
- 研究方法
- 创新点
- 预期成果
- 实施计划
- 保障条件

### 11. 质量检查与追问

目标：在生成后检查是否满足申报质量要求，并针对薄弱部分追问。

检查维度：

- 问题是否具体
- 方法是否可执行
- 成果是否可复用
- 论证是否有依据
- 是否符合申报模板
- 是否体现专科院校场景

### 12. 定稿导出

目标：输出老师可继续修改或提交的材料。

第一版 demo 可输出 Markdown 版申报书；后续可支持 DOCX 模板填充。

## 关键确认点

系统必须在以下节点暂停确认：

1. 课题方向确认
2. 研究问题确认
3. 方法路径确认
4. 成果形式确认
5. 申报书初稿确认

## 第一版不做

1. 不做完整科研生命周期。
2. 不做自动实验或数据分析。
3. 不做论文投稿支持。
4. 不做学校系统集成。
5. 不做真实文献检索的复杂自动化，先用人工提供材料或模拟材料支撑 demo。
